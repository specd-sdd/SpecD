# Exploration Context: suggest-implementation-and-spec-deps

Generated: 2026-08-16

## Problem Statement
`specd` needs automated, static-analysis-driven suggestion mechanisms for discovering implementation links (file + symbols) and spec-to-spec dependencies (`dependsOn`). Currently, spec authors manually correlate specs with implementation code and dependOn relations. We proved through prototype testing in `dev/scripts/suggest-spec-implementation.ts` that static AST analysis, name pattern matching, BM25 symbol search, and upstream graph impact traversal (`maxDepth = 2`) can discover implementation links and spec dependencies with 100% determinism, 0 LLM tokens, and <200ms performance.

Now, we need to formalize this capability into reusable SDK Use Cases and CLI subcommands.

---

## Architecture & Package Boundaries

### 1. Package Dependency Hierarchy
```
core        (Domain & Kernel - NO dependency on code-graph)
code-graph  ➔ core
sdk         ➔ core, code-graph (Orchestration layer combining Core domain with Code-Graph intelligence)
cli         ➔ core, code-graph, sdk
```

### 2. Location of Use Cases
The new suggestion use cases MUST live in `@specd/sdk` (`packages/sdk/src/orchestration/`), because they require combining `@specd/core` (config, domain entities, spec-lock persistence) with `@specd/code-graph` (SQLite provider, AST symbol search, file impact traversal). They MUST NOT live in `@specd/core` to preserve core's independence from code-graph.

## Key Use Cases & Design Requirements

### 1. `SuggestImplementationLinks` Use Case (`packages/sdk/src/orchestration/suggest-implementation-links.ts`)
- **Purpose**: Deduces suggested implementation files and symbols for target specs.
- **Strategies**:
  1. AST Symbol Extraction from spec code blocks (`spec.md`).
  2. Naming convention derivatives (PascalCase, kebab-case, sub-path matching).
  3. BM25 similarity queries in `code-graph` SQLite database.
  4. Production file pattern matching (excluding `test/`, `.test.ts`, `.spec.ts`).
- **Scoring & Confidence**: Assigns `HIGH`, `MEDIUM`, or `LOW` confidence badges and scores.
- **Options**: `{ specId?: string; workspace?: string; apply?: boolean; confidenceThreshold?: 'HIGH' | 'MEDIUM' }`.

### 2. `SuggestSpecDependencies` Use Case (`packages/sdk/src/orchestration/suggest-spec-dependencies.ts`)
- **Purpose**: Deduces `dependsOn` relations between specs based on production code imports.
- **Strategies**:
  1. Multi-workspace global `fileToSpecMap` across all monorepo packages.
  2. Upstream file impact analysis (`analyzeFileImpact` with `direction: 'upstream'`, `maxDepth: 2` to navigate barrel re-exports like `@specd/sdk`).
  3. Noise filtering (ignores test files, same-file co-location, and LOW confidence candidates).
- **Options**: `{ specId?: string; workspace?: string; apply?: boolean }`.

### 3. Additive / Cumulative Mutation Policy (`apply: true`)
When `apply: true` (or `--apply` flag) is specified:
- **Implementation Links**: Performs a set union of `file` and `symbols`. Does NOT delete existing confirmed implementation links in `spec-lock.json`.
- **Spec Dependencies**: Performs an array union of `dependsOn` spec IDs. Does NOT remove existing dependencies.

### 4. Post-Apply Validation & Diagnostic Safety Net
After applying mutations to `spec-lock.json`:
- Executes post-validation (`validateSpec`) on affected specs.
- If any specs become invalid (e.g., mismatch between `spec.md` requirements and `spec-lock.json` dependencies):
  - Renders a diagnostic list of invalid specs and their specific failure reasons.
  - Suggests creating a change to align `spec.md` requirements:
    `"⚠️ Specs are invalid after updating dependencies. Run 'specd changes create align-spec-deps --spec <id> ...'"`

### 5. System Cache Standardization (`.specd/cache/`)
- Cache file path: `.specd/cache/implementation-suggestions.json`.
- Uses `specd`'s standard `.specd/cache` folder (already managed in `.gitignore`).
- Includes freshness metadata (`updatedAt`, `contentHash`, `mtimeMs`).
- Invalidates per-spec entries when spec files or code-graph database are updated.

## CLI Integration (`@specd/cli`)

Adds two subcommands under existing command groups:

1. **`node packages/cli/dist/index.js spec implementation suggest [<specPath>] [--apply] [--confidence <HIGH|MED>] [--format text|json|toon]`**
2. **`node packages/cli/dist/index.js spec deps suggest [<specPath>] [--apply] [--format text|json|toon]`**
