# Exploration: cli-input-dash-stdin

Generated: 2026-11-06
Updated: 2026-11-06 (scope expanded — naming decision)

## Problem statement

1. CLI content input APIs were inconsistent (`--file`+implicit stdin vs `--input`+`-`).
2. More important: `project update-metadata` is misnamed — it only writes the single
   LLM-optimized project context string (`optimized.context`), not general metadata.

## Approach / solution outline (current — user confirmed direction)

**Do NOT** mirror `specs optimizations` as a plural group on project.

Reason: specs have **two** fields (`optimizedDescription`, `optimizedContext`); project
has **one** (`optimized.context`). Plural `project optimizations` would be dishonest.

Preferred surface (user confirmed): a single noun command group:

```
project optimized-context get
project optimized-context set [--input <path|-> | --text <string>]
project optimized-context clear
```

Inline flag default for design: `--text` (avoid `set --optimized-context` redundancy
on a command already named `optimized-context`). Agent template migrates from
`project update-metadata --optimized-context "..."` → `project optimized-context set --text "..."`.
`--input <path|->` remains the file/stdin form; no implicit stdin.

- Remove / mark removed: `project update-metadata` (same arc as removed `spec update-metadata`)
- Keep: `project metadata` = full `project-metadata.json` dump (freshness + optimized + generated)
- Input convention on `set`: `--input <path|->` (and likely a direct text flag); no implicit stdin
- Shared CLI helper `readInput(path)` for `--input`/`-` still desirable (used by specs optimizations too)
- Migrate callers: ONLY the source template
  `packages/skills/.../specd-project-context-optimizer/SPECD-AGENT.md.tpl`
  (and its unit test expectation). Do NOT edit generated copies such as
  `.claude/agents/specd-project-context-optimizer.md` — those refresh via
  `project update` / plugin install. Template currently references
  `project update-metadata --optimized-context "..."` (flag that does not even
  exist on CLI today).

**Post-change follow-up (manual / after implement):** run `specd project update`
to regenerate installed agent instruction files from the updated template. Not
part of editing generated files in-repo during the change.

## Earlier approach (superseded)

Original narrow plan was only rename `--file` → `--input` on `update-metadata`. Then we
considered mirroring `project optimizations get|set|clear`. Both superseded by
`project optimized-context`.

## Design decisions (confirmed)

- Pattern: **always `--input` and `-` for stdin** (user explicit)
- Not keeping `--file` as alias
- Not keeping implicit stdin when no flag is provided
- Schema `--file` for path-based schema mode is out of scope (not content payload)
- Graph/implementation `--file` path selectors are out of scope

## Agreements reached

- Create change `cli-input-dash-stdin`
- Primary spec: `cli:project-update-metadata`
- Optionally extract shared `readInput` used by optimizations + update-metadata

## Steps / plan

1. Design: rewrite Input payload requirement to `--input <path|->`; update verify scenarios
2. Implement: shared helper + update-metadata command + docs + tests
3. Keep optimizations on shared helper if extracted
4. Verify / archive later

## Rejected alternatives

- Keep `--file` with implicit stdin (current code) — rejected; inconsistent
- Dual aliases `--file` and `--input` — not requested; prefer single flag
- Unify schema/graph `--file` path selectors into `--input` — out of scope; different meaning
