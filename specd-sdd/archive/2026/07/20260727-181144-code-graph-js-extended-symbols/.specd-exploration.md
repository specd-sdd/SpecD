# Exploration Context: code-graph-js-extended-symbols

Generated: 2026-07-27

## Problem Statement

When analyzing JavaScript and TypeScript files using `@specd/code-graph` (specifically `TypeScriptLanguageAdapter` in `packages/code-graph/src/infrastructure/tree-sitter/typescript-language-adapter.ts`), non-standard or legacy structural patterns are not extracted as symbols or relations.

Specific case raised by the user:

```javascript
IcCMS.Article = (function(){
    return {
        // Key/property of an anonymous object returned inside a closure:
        generateAltHeadlines: function(config, data) { ... }
    };
})();
```

### Why it currently fails in `@specd/code-graph`

1. **Member assignment (`member_expression`)**: `IcCMS.Article = ...` is an `assignment_expression` targetting a member, not a `variable_declaration` (`var`/`let`/`const`). The current adapter ignores `assignment_expression` AST nodes ([typescript-language-adapter.ts:L333-L345](file:///Users/monki/Documents/Proyectos/specd/packages/code-graph/src/infrastructure/tree-sitter/typescript-language-adapter.ts#L333-L345)).
2. **Anonymous IIFE**: The outer function has no name (`getName()` returns `undefined`).
3. **Object Literal Methods (`pair` / `property_definition` AST nodes)**: Properties inside returned objects (`generateAltHeadlines: function(...)`) are tree-sitter `pair` nodes. The adapter currently only scans `method_definition` inside class declarations, omitting functions assigned inside object literals.
4. **Scoping & Call Facts**: `IcCMS.Article.generateAltHeadlines(...)` call sites cannot be linked to the extracted function without qualified name construction (`IcCMS.Article.generateAltHeadlines`).

---

## Approach & Solution Outline

Extend `TypeScriptLanguageAdapter` in `packages/code-graph/src/infrastructure/tree-sitter/typescript-language-adapter.ts` to inspect additional Tree-sitter AST nodes and convert them directly into `@specd/code-graph`'s 7 canonical `SymbolKind`s (`Function`, `Method`, `Class`, `Variable`, `Type`, `Interface`, `Enum`) without altering domain schemas or downstream graph persistence.

### Conversion Mapping Matrix

| AST Node (Tree-sitter)  | Syntax / Condition                                                                    | Canonical `SymbolKind` | Resulting Symbol / Qualified Name                                          |
| :---------------------- | :------------------------------------------------------------------------------------ | :--------------------- | :------------------------------------------------------------------------- |
| `assignment_expression` | Left is `member_expression` (`A.B = ...`), Right is `function`/`arrow_function`       | `SymbolKind.Method`    | `IcCMS.Article.generateAltHeadlines`                                       |
| `assignment_expression` | Left is `member_expression` (`IcCMS.Article = ...`), Right is IIFE / Object           | `SymbolKind.Variable`  | `IcCMS.Article`                                                            |
| `assignment_expression` | CommonJS (`exports.foo = ...` or `module.exports.foo = ...`)                          | `SymbolKind.Function`  | Symbol `foo` + `RelationType.Exports`                                      |
| `pair`                  | Key-value in Object Literal where value is `function`, `arrow_function` or ES6 method | `SymbolKind.Method`    | `generateAltHeadlines` (or qualified `IcCMS.Article.generateAltHeadlines`) |
| `pair`                  | Key-value in Object Literal with non-function scalar/data value                       | `SymbolKind.Variable`  | `settings` / `config`                                                      |
| `field_definition`      | Class field assigned to `arrow_function` (`handleClick = () => {}`)                   | `SymbolKind.Method`    | `MyClass.handleClick`                                                      |
| `field_definition`      | Class field assigned to non-function scalar value (`count = 0`)                       | `SymbolKind.Variable`  | `MyClass.count`                                                            |
| `variable_declarator`   | Variable assigned via HOF (`const foo = memoize(...)` or `withAuth(...)`)             | `SymbolKind.Function`  | `foo`                                                                      |
| `object_pattern`        | Destructuring (`const { generateAltHeadlines, parse } = utils`)                       | `SymbolKind.Variable`  | Extracts `generateAltHeadlines` and `parse` individually                   |
