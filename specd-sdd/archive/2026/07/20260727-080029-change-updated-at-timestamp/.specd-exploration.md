# Exploration Context: change-updated-at-timestamp

## Problem Statement

The user requested to bring the implementation of `updatedAt` for changes from the `feat/user-interface` branch (located in `../specd-worktrees/feat-user-interface`) into the main codebase. Currently, `Change` entity and its persisted manifest lack an explicit `updatedAt` timestamp tracking field, which limits cash/revision checking and last modified tracking across the UI and core services.

## Solution / Approach

1. **Domain Layer (`@specd/core`)**:
   - Update `Change` domain entity to store `_updatedAt: Date` (defaulting to `createdAt` if not provided).
   - Enforce invariant `updatedAt >= createdAt`.
   - Provide getter `get updatedAt(): Date` returning a copy.
   - Add `touch(at?: Date)` to mutate timestamp when needed.
2. **Infrastructure / Persistence Layer (`@specd/core`)**:
   - Update `manifest.ts` schema with optional `updatedAt: z.string().optional()`.
   - Update `change-repository.ts` to serialize `updatedAt`.
   - Implement `deriveManifestUpdatedAt(manifest: ChangeManifest): Date` as a fallback for legacy manifests missing `updatedAt` (finds max `at` in history or falls back to `createdAt`).
3. **Application Layer (`@specd/core`)**:
   - Update `save-change-artifact` to touch/update `updatedAt`.
   - Update `get-status` to support revision/`ifModifiedSince` comparison using `updatedAt.getTime()`.
4. **UI Layer (`@specd/ui`)**:
   - Update change status UI views and hooks (`use-changes-read`) to utilize `updatedAt`.
