# Exploration: remove legacy metadata skill

Generated: 2026-07-23

## Problem statement

Remove the obsolete `specd-metadata` skill from `@specd/skills` and every active reference to it. Metadata optimization is now performed by specialized agents, so the standard skill duplicates and conflicts with the intended interface.

The user explicitly confirmed direct removal. There are no users yet, so no compatibility alias, deprecation period, migration guide, or fallback command is required.

## Intended solution

- Remove the `packages/skills/templates/skills/specd-metadata/` template directory, including `SKILL.md.tpl` and `skill.meta.json`.
- Remove `specd-metadata` from every plugin `skillFrontmatter` map.
- Update template/spec references that enumerate the standard skills.
- Replace workflow guidance that tells users to invoke the old skill with guidance to launch the appropriate specialized agent, normally `specd-spec-context-optimizer` for per-spec optimization.
- Remove generated or installed copies of the old skill through the repository's normal skills synchronization/rendering workflow.
- Remove the legacy development skill `dev/ai-agents/skills/specd-spec-metadata/SKILL.md` if it remains an active source or reachable artifact; it is a legacy skill rather than one of the specialized agents and retaining it would contradict the intended end state.

## Risks and verification targets

- Ensure bundle discovery/rendering tolerates the removed directory and that no plugin still exposes `specd-metadata`.
- Ensure all generated skill directories are synchronized after source removal, so the old skill does not remain invocable locally.
- Ensure `specd-archive` guidance points to the correct per-spec optimizer agent and remains sensible for runtimes without delegated-agent capability; the agents specification defines a file-based/manual fallback when `agents` is unavailable.
- Update the template-listing spec and its verification scenarios; otherwise implementation would intentionally violate the existing contract.
- Exclude historical archives and unrelated `.specd-metadata.yaml` references from cleanup. They document archived history or the persisted metadata mechanism, not the removed skill.

## Rejected alternatives

- Compatibility alias or migration path: rejected by the user because no users exist yet.
- Removing all metadata infrastructure: rejected because deterministic metadata generation, persistence, freshness, and optimized-field updates remain required.
- Retaining the legacy `dev/ai-agents` skill alongside specialized agents: undesirable because it preserves a duplicate, obsolete invocation path.
