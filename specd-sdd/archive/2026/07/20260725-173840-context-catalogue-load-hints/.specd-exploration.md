# Exploration: context-catalogue-load-hints

## Problem statement

`change context` shows optimized context inline for full-mode specs, but non-full specs appear in an `## Available context specs` catalogue with a single hint:

> Use `specd changes spec-preview <change-name> <specId>` to load the merged full content of any change spec you need.

This is misleading in two ways:

1. **Dependency / include-pattern specs** (sources: `specDependsOn`, `includePattern`, `dependsOnTraversal`) are not in `change.specIds` — `spec-preview` fails for them. The correct drill-down is `specd specs context <specId>` (optimized canonical context).
2. **`spec-preview` is not optimized** — it shows raw merged artifacts for change specs with deltas, which is correct for merged review but different from the optimized context the agent saw in the main block.

`project context` has the same catalogue pattern but **no hint at all** today. It cannot use `spec-preview` (no change scope). Non-full specs should point to `specs context <specId>`.

## Approach / solution outline

Extract agent-facing markdown rendering into **SDK presentation helpers**. Core stays structured; CLI becomes a thin adapter that calls the helpers.

### `sdk:context-markdown` (new spec)

Add pure presentation functions in `@specd/sdk`:

- `changeContextToMarkdown(context: CompileContextResult, options: { changeName: string; includeFingerprint?: boolean })`
- `projectContextToMarkdown(context: GetProjectContextResult)`

Location: `packages/sdk/src/presentation/` with shared internals for catalogue tables and hint resolution.

**Hint routing** (`resolveLoadHint` / catalogue partition):

| Catalogue group (`mode !== 'full'`) | Hint                                         | Why                                                           |
| ----------------------------------- | -------------------------------------------- | ------------------------------------------------------------- |
| `source: 'specIds'`                 | `specd changes spec-preview <name> <specId>` | Change-scoped: deltas or new; not correct via `specs context` |
| other sources                       | `specd specs context <specId>`               | Canonical                                                     |

Separate tables per hint group; `dependsOnTraversal` under `### Via dependencies`.

`projectContextToMarkdown` never mentions `spec-preview` (no change scope).

### `cli:change-context` + `cli:project-context`

Refactor text mode to delegate entirely to SDK helpers — remove inline markdown assembly. CLI retains: flags, use-case invocation, stderr warnings, exit codes, json/toon passthrough.

Optionally keep splitting catalogue by `dependsOnTraversal` sub-heading (already in CLI today; move to SDK helper).

## Design decisions

- **SDK presentation helpers** — markdown + hints live in `@specd/sdk` for reuse by CLI, MCP, future hosts.
- **CLI thin adapter** — no inline markdown assembly in CLI commands.
- **`project context` never suggests `spec-preview`** — no change name exists in that command's scope.
- **Two commands for change context drill-down** is intentional:
  - `spec-preview` = merged artifact review (change specs only)
  - `specs context` = optimized canonical context (deps and any spec)
- Do **not** try to make `spec-preview` return optimized context in this change — out of scope.

## Rejected alternatives

- **New unified command `change spec-context`** — deferred; hints fix is smaller and sufficient for now.
- **Core exposes `recommendedLoadCommand` per entry** — unnecessary; CLI can derive from `source` + whether command is change-scoped.
- **Default `contextMode: hybrid` + `--include-change-specs`** — token cost; separate concern.
