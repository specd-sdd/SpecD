# Exploration: explicit graph config outside VCS

## Intent

Correct the graph CLI context resolution so that a valid configuration selected
with `--config` can be used outside a VCS repository. Repository discovery
remains a bootstrap-only requirement.

## Observed regression

`graph stats --config <path>` now routes through
`resolveGraphCliContext`. In its configured branch, that resolver obtains the
project root from the explicit config and then unconditionally calls
`resolveRepoRoot(projectRoot)`. Consequently, a valid forced config in a
directory that is not inside a repository fails before the graph provider can
be opened.

Before the shared-context routing, the stats command opened the host with the
provided config path and did not require VCS discovery. This is a behavior
regression for the explicit configuration path.

## Contract and scope

`core:config` defines `--config` as a forced file-entry configuration path,
separate from configuration discovery. That contract permits config-backed
projects outside VCS. The graph CLI must preserve that distinction:

- Explicit-config mode: resolve and open the specified project configuration
  without requiring a repository root; VCS-derived health information may be
  unavailable/unknown.
- Bootstrap mode: continue to require repository discovery because it has no
  explicit project configuration to establish context.

The behavioral ownership is `cli:graph-cli-context`; `cli:graph-stats` is the
user-visible command that exposed the regression. `core:config` is a source
contract and does not need a normative change.

## Affected implementation and tests

Primary production target: `packages/cli/src/commands/graph/resolve-graph-cli-context.ts`.
Primary regression coverage: resolver/context tests and graph stats tests for a
forced config under a non-VCS temporary directory. Existing bootstrap tests
must continue to assert failure outside a repository.

Graph analysis reports broad downstream reach for the shared resolver (14
direct dependencies, 132 indirect dependencies, 21 transitive dependencies,
176 affected files), so the implementation must limit the semantic change to
the explicit-config branch and preserve context fields expected by graph
commands.

## Non-goals

- Do not alter config discovery semantics.
- Do not weaken VCS validation in bootstrap mode.
- Do not change the Ladybug deprecation scope or reintroduce Ladybug-related
  terminology into SQLite graph-store specifications.
