# Review exploration

## Current decision

The change centralizes the isolated graph-index worker in Code Graph, retains SDK
ownership of project-index orchestration, and keeps the CLI as the delivery adapter.
Forced indexing is a logical `clear()` rebuild. Physical SQLite recreation is a
closed-store, force-only recovery after a typed storage-open error.

## Full-verification findings to resolve

1. `runIndexProjectGraph` must delegate prepared open-provider indexing through
   `createIndexProjectGraph()` rather than call `provider.index()` directly, with a
   test asserting that seam.
2. SQLite verification must say that only a forced SDK reindex may close, recreate,
   reopen, and retry after a typed recoverable open failure; ordinary reads and
   non-forced index operations propagate the error unchanged.
3. Graph Store verification must say that `recreate()` leaves storage closed and
   ready to be explicitly opened before a fresh index, rather than implying it is
   immediately indexable.

## Boundaries and affected implementation

- `packages/sdk/src/orchestration/run-index-project-graph.ts`
- `packages/sdk/test/orchestration/run-index-project-graph.spec.ts`
- `packages/code-graph/src/application/use-cases/index-project-graph.ts`
- Relevant SQLite and provider lifecycle tests.

All target workspaces are owned. Full hooks and the packaged `graph index --force`
smoke passed before this review; the remaining work is spec alignment plus the SDK
application-use-case delegation.
