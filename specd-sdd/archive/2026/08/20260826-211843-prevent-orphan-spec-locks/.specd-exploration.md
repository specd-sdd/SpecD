## Motivation & Problem

- Raw filesystem enumeration found orphan `spec-lock.json` sidecars in directories with no canonical `spec.md` (e.g. `specs/core/archive-list-entry/spec-lock.json` and `specs/core/core/change-repository/spec-lock.json`).

### Why Did This Happen in the First Place? (Root Cause Analysis at Source)

1. **Source of the invalid spec ID**:
   - The canonical spec identity in `specs/core/archived-change-index-entry` was named `archived-change-index-entry`.
   - In TypeScript source code, the domain entity was named `ArchiveListEntry` in `archive-list-entry.ts`.
   - When implementation tracking was added via `specd changes implementation add`, the user/agent guessed the spec ID as `core:archive-list-entry` from the class/filename rather than using the canonical spec ID.
   - For `core:core/change-repository`, the workspace prefix was accidentally doubled (`core:` + `core/change-repository`).
2. **Missing validation at link addition (`UpdateImplementationTracking`)**:
   - `UpdateImplementationTracking._validateMutation` verified only that the file existed on disk (`_requireExists(file)`).
   - It **never validated `specId`** against the change's `specIds` or against the workspace `SpecRepository`.
   - Any invalid, typo-ridden, or nonexistent `specId` was silently accepted and written to `manifest.json`.
3. **Dangling links after removing specs from changes**:
   - When a new spec was removed from a change (`EditChange`), its implementation links remained dangling in `manifest.json`.
4. **Missing sweep & self-healing in `RefreshImplementationTracking`**:
   - `RefreshImplementationTracking` swept for deleted files on disk, but did not sweep for dangling links pointing to nonexistent specs.
5. **Blind publication in `ArchiveChange` & missing guard in `FsSpecRepository`**:
   - `_prepareArchivePlan` blindly added all `[...implementationBySpecId.keys()]` into `publicationSpecIds`, creating persisted `spec-lock.json` sidecars for nonexistent specs.
   - `FsSpecRepository.publish` allowed creating a brand new spec directory containing only `spec-lock.json` when `publication.artifacts` was empty (`[]`).

## Approaches Explored & Agreed Strategy

- **Self-Healing & Defense-in-Depth Architecture**:
  1. **Validation at link insertion (`UpdateImplementationTracking`)**:
     - When adding an implementation link (`action: 'add'`), `_validateMutation` asserts that `input.specId` is either declared in `change.specIds` or exists in the project's canonical `SpecRepository`.
     - Rejects unknown spec IDs immediately with `SpecNotFoundError(specId)`.
  2. **Self-Healing Spec Sweep (`RefreshImplementationTracking`)**:
     - `_specSweep` checks all links in `change.implementationLinks`. If a link points to a `specId` that is not in `change.specIds` and not found in canonical `SpecRepository`, it is automatically pruned.
  3. **Auto-refresh on scope changes (`EditChange`)**:
     - When `specIds` change in a change (`specIdsChanged === true`), `EditChange` invokes `RefreshImplementationTracking` to immediately clean up any dangling links from removed specs.
  4. **Safe Discard in Archive (`ArchiveChange._prepareArchivePlan`)**:
     - If any nonexistent spec ID is encountered in `implementationBySpecId`, it is safely discarded from publication (`continue`), without failing or creating orphan sidecars.
  5. **Repository guard (`FsSpecRepository.publish`)**:
     - `publish` throws `SpecPublicationError` if attempting to create a new spec directory when `publication.artifacts` is empty.

## Decisions & Code Actions

- **Decision 1 (`UpdateImplementationTracking`)**:
  - Injected `specRepositories?: ReadonlyMap<string, SpecRepository>` into `UpdateImplementationTracking` and composition wiring (`resolveUpdateImplementationTrackingDeps`).
  - Added validation in `_validateMutation` for `action === 'add'`: if `!change.specIds.includes(input.specId)`, lookup spec in `_specRepositories`. Throw `SpecNotFoundError(input.specId)` if absent.
  - Touched: `packages/core/src/application/use-cases/update-implementation-tracking.ts`, `packages/core/src/composition/use-cases/update-implementation-tracking.ts`.
- **Decision 2 (`RefreshImplementationTracking`)**:
  - Added `_specSweep(freshChange)` to prune dangling implementation links whose specId is neither in `change.specIds` nor in `specRepositories`.
  - Injected `specRepositories` in composition wiring.
  - Touched: `packages/core/src/application/use-cases/refresh-implementation-tracking.ts`, `packages/core/src/composition/use-cases/refresh-implementation-tracking.ts`.
- **Decision 3 (`EditChange`)**:
  - Added optional `refreshImplementationTracking` dependency.
  - On `persisted.invalidated` (when `specIds` change), triggers `_refresh.execute({ name })`.
  - Touched: `packages/core/src/application/use-cases/edit-change.ts`, `packages/core/src/composition/use-cases/edit-change.ts`.
- **Decision 4 (`ArchiveChange._prepareArchivePlan`)**:
  - Safely discards nonexistent spec publication candidates (`implementationBySpecId.delete(specId)` and `continue`).
  - Touched: `packages/core/src/application/use-cases/archive-change.ts`.
- **Decision 5 (`FsSpecRepository.publish`)**:
  - Added guard throwing `SpecPublicationError` when `!specDirExists && publication.artifacts.length === 0`.
  - Touched: `packages/core/src/infrastructure/fs/spec-repository.ts`.
- **Decision 6 (Comprehensive Regression Tests)**:
  - Added unit tests in `update-implementation-tracking.spec.ts`, `refresh-implementation-tracking.spec.ts`, `edit-change.spec.ts`, `archive-change.spec.ts`, and `spec-repository.spec.ts`.

## Consolidation & Audit Summary

### 1. Root Cause & Solution Summary

- **Root Cause**: Invalid spec IDs could be recorded due to lack of `specId` validation in `UpdateImplementationTracking`, lingering links from removed specs in `EditChange` were not swept, and `ArchiveChange` blindly created physical lockfiles for any string in `implementationLinks`.
- **Resolution**:
  1. Early validation in `UpdateImplementationTracking` prevents typos at input time.
  2. Self-healing spec sweep in `RefreshImplementationTracking` prunes dangling links.
  3. `EditChange` triggers refresh automatically on scope modification.
  4. `ArchiveChange` safely discards nonexistent specs.
  5. `FsSpecRepository` guards against creating empty spec directories with only lock sidecars.
