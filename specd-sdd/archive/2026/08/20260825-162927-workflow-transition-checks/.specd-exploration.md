## Problem statement

Lifecycle UX and engine logic are split across layers that disagree:

- `LifecycleEngine.evaluate` knows the graph (`VALID_TRANSITIONS`), artifact `requires`, approval routing, and `_nextAction`.
- It does **not** know `requiresTaskCompletion`. `availableTransitions` can list `verifying` while execute would fail on incomplete tasks.
- `_nextAction` in `implementing` **always** recommends `/specd-implement`, even at 7/7 tasks (observed in exploration; still true in `lifecycle-engine.ts` ~L723–729).
- `GetStatus` runs `CountTasks` **after** `evaluate` and only attaches `taskCompletion` onto artifact rows.
- `TransitionChange` evaluates, then separately enforces tasks and throws `InvalidStateTransitionError`.
- Spec dependency mismatch (`ArchiveDependencyMismatchError`) is discovered at **archive**, after the whole workflow. User wants it at **ready** while still in design.

User intent: one evaluation model for “can I go from A to B?” that status, repair guide, nextAction, and execute all share — so later slices (dry-run, more checks, optional implementing) do not throw away the first implementation.

## Approach / solution outline

**Not** three output buckets (`schemaBlockers` / `taskBlockers` / `platformBlockers`). User rejected that as an accident of authorship.

**Yes:**

1. Enumerate candidate transitions first (graph edges, or a requested `--target`).
2. Attach checks to each candidate and run them in order.
3. Every check has the same result shape (`pass` | `fail` | `skip`).
4. `allowed` = no blocking `fail`.
5. `validTransitions` / `availableTransitions` / `nextAction` are **projections** of that evaluation, never parallel if-ladders.

### Check contract (stable; do not reinvent later)

Two types:

**Registration / module**

- `id` (stable): e.g. `protocol.edge`, `workflow.requires`, `workflow.taskCompletion`, `deps.consistent`
- `origin`: `schema` | `core` (where the _definition_ comes from, not an output bucket)
- `blocking`, `failFast` (`protocol.edge` is fail-fast)
- `needs`: which snapshots (schema, artifact verdicts, task counts, merged specs, …) so `LifecycleEngine` stays **pure** (no I/O)

**Result row** (one entry in `checks[]` on a transition attempt)

- `id`, `outcome` (`pass` | `fail` | `skip`), `code`, `message`, `details` (artifactId, counts, resolve command), `isSkippable` / `bypassFlag` aligned with existing `LifecycleBlocker`

Map execute failures to existing `TransitionFailureReason` where possible (`invalid-transition`, `incomplete-artifact`, `incomplete-tasks`, `approval-required`, `gate-not-required`). Dry-run/status return the same `checks[]` without throwing.

### Binding: three layers (not a giant static matrix)

Authoring DX the user wanted: extra **core** checks hang off a target:

```ts
{ target: 'ready', checks: ['deps.consistent'] }
```

Do **not** copy universal/schema checks into every row.

| Layer      | What                                           | How bound                                                                                       |
| ---------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Always     | `protocol.edge`                                | every attempted `from → requested`                                                              |
| Schema     | `workflow.requires`, `workflow.taskCompletion` | from `workflow[]` of the **effective** target                                                   |
| Core table | e.g. `deps.consistent`                         | `{ target: 'ready', checks: [...] }` plus `archive` operation key (archive is not a transition) |

**Source of truth for core extras:** the binding table (transition/target → check ids). Check modules implement `evaluate`. Do not maintain both `appliesTo` on every check **and** the table (drift).

**Evaluation algorithm** is transition-centric: start from transitions, attach checks. **Registry of implementations** is check-centric. Docs/tests may show a generated transitions×checks view.

`target` means **entering** that state (`verifying → done` uses the `done` row), not “checks while sitting in done” (leaving `done` toward `archivable` is the `archivable` / `archive` binding).

### Routing vs checks

- `protocol.edge` is check 0: is `from → requested` in `VALID_TRANSITIONS`?
- Spec/signoff **routing** is not a failed edge: `ready → implementing` with spec gate on is a **legal** edge; `effective` becomes `pending-spec-approval`.
- `pending-spec-approval → implementing` is **not** a legal transition; human `approve spec` is a different command.
- Invariant “do not persist `implementing` without spec approval” can be a later core check; not required in this change if routing+throws already hold — design should not close the door (`skip` when gate off).

### `deps.consistent`

Same runner for:

- transition **to `ready`** (hard blocker — fail cheap in design)
- **archive** operation (safety net, not first discovery)

Today: `ArchiveChange` preflight vs `ArchiveDependencyMismatchError` (`ARCHIVE_DEPENDENCY_MISMATCH`) when sidecar active and extract ≠ resolved persisted/manifest deps (`archive-change.ts` ~L848–857). Generalize code name if needed so it is not archive-only.

`skip` only when there is nothing to extract (e.g. sidecar inactive), not “defer to archive”.

## This change — in scope

Foundation that later work plugs into:

- Check result contract + ordered evaluation per transition attempt
- Binding layers (always / schema / core table)
- Checks: `protocol.edge`, `workflow.requires`, `workflow.taskCompletion`, `deps.consistent` (ready + archive reuse)

## Design decisions (confirmed by user)

- Treat exploration doc as non-normative; slice work but **one program** so slice 1 is not throwaway.
- Unified workflow **checks**, not schema/task/platform blocker arrays.
- Check 0 = protocol/graph edge; invalid target uses the same object as task failure.
- Registry/contract for checks so later checks are new modules + binding rows.
- Binding table `{ target, checks }` for **core extras**; evaluation starts from transitions then attaches checks.
- `deps.consistent` **belongs at ready** (hard), archive as second binding — user explicitly corrected “not in first slice / not needed at ready”.
- Spec gate applies to post-ready shortcuts **if** skip-implementing is ever done (later); tests always on/off.
- No autonomous `changes approve`.
- English artifacts.

## Rejected alternatives

- Universal “any state → any previous”.
- Put all checks inside `LifecycleEngine` including I/O.
- Thin `_nextAction` patch without evaluation contract (obsolete in minutes).
- `EvaluateTransition` as a **third** path beside GetStatus/TransitionChange.
- Empty `PlatformGateRegistry` with no-op runners.
- Three named blocker arrays on the public evaluation DTO.
- Static full matrix as source of truth (combinatorial; archive ≠ state; schema cells data-driven).
- Listing `protocol.edge` / requires / taskCompletion by hand on every target row.
- Skip implementing / multi-hints from `ready` in this change.
- Discovering dep mismatch only at archive.
