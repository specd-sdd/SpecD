# Exploration Context: start-implementation-tracking

Generated: 2026-08-26

## Problem Statement

Currently, implementation tracking in specd is implicitly triggered by the state transition to `implementing` (`hasEverReachedImplementing` checking `evt.type === 'transitioned' && evt.to === 'implementing'`). There is no explicit mechanism for operators or agents to initiate implementation tracking on demand (e.g. before state transition or independently) via a dedicated CLI command like `specd changes implementation start <name>`.

Additionally, the detection baseline currently relies solely on historical state events rather than an explicit persisted field in the change manifest (`manifest.json`), which makes decoupled tracking or explicit activation impossible.

## Proposed Solution Outline

1. **CLI Command**:
   - Expose `specd changes implementation start <name>` under the `specd changes implementation` command group in `@specd/cli`.
   - Running `start` marks implementation tracking as active for the change and records the start baseline/timestamp if not already started.

2. **Domain Entity & Manifest Persistence (`manifest.json`)**:
   - Add a field (e.g., `isImplementationTrackingActive` / `implementationStartedAt` or boolean tracking flag) to the `Change` domain entity in `packages/core/src/domain/entities/change.ts`.
   - Update `manifest.json` schema and serialization in `packages/core/src/domain/entities/change.ts` and `packages/core/src/infrastructure/repositories/fs-change-repository.ts` (governed by `core:change-manifest`).

3. **Backward Compatibility**:
   - When a change transitions to `implementing` for the first time (`ready -> implementing` or similar), if the tracking flag has not yet been set to `true`, the transition logic automatically sets it to `true` (and records the timestamp/baseline).
   - This ensures existing workflows and changes continue to track implementation files seamlessly without breaking changes.

4. **Tracking Execution / Refresh**:
   - In `RefreshImplementationTracking` and related detection routines, check the persisted tracking flag/state on the `Change` entity instead of exclusively relying on `hasEverReachedImplementing`.

## Design Decisions & Agreements

- Manifest file format is `manifest.json` (inside `.specd/changes/<changeDir>/` / `specd-sdd/changes/<changeDir>/`).
- Adding `start` subcommand must be idempotent: calling `start` when already started is a safe no-op or returns current active status.
- Retain backwards compatibility on `transition to implementing`.

## Open Questions for `/specd-design`

- Should `start` also take an optional `--at <timestamp/ref>` or always capture `now()` / current HEAD ref?
- Should `start` be a standalone usecase (`StartImplementationTracking`) or a method/variant in `UpdateImplementationTracking`?
