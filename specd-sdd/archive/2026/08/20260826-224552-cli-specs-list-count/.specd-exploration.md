## Motivation & Problem

- CLI users and agents need a quick way to count specs without listing all individual spec entries and metadata.
- Adding `--count` flag to `specd specs list` / `specd spec list` allows retrieving the total spec count globally and per workspace, with support for `--workspace` filtering and `text`, `json`, and `toon` output formats.
- `--count` is mutually exclusive with `--summary` because `--count` suppresses individual spec listing and summary extraction.

## Approaches Explored & Agreed Strategy

- Add `--count` boolean option to `spec list` command in `@specd/cli`.
- Enforce validation: throw `CliValidationError` when both `--count` and `--summary` are provided.
- In `spec list` command action, if `opts.count` is `true`:
  - Query `kernel.specs.list.execute` passing workspace filters when provided.
  - Calculate `total` count across visible workspaces and count per workspace.
  - In `json` / `toon` format: output structured object `{ total: number, workspaces: Array<{ name: string, count: number }> }`.
  - In `text` format:
    - If multiple visible workspaces: print `Total: <total>\n\nWorkspaces:\n  <ws1>: <count1>\n  <ws2>: <count2>`.
    - If a single workspace is visible via `--workspace <name>`: print `<ws>: <count>`.

### 6. Spec & Verification Guidance

- **Requirements**:
  - `spec list --count` SHALL display the total count of specs across all configured workspaces and per-workspace counts.
  - `spec list --count --workspace <name>` SHALL display the total count for the specified workspace(s).
  - `spec list --count` and `spec list --summary` SHALL be mutually exclusive; running both SHALL exit with code 1 and throw `CliValidationError`.
  - `spec list --count --format json` SHALL output `{ total: number, workspaces: Array<{ name: string, count: number }> }`.
  - `spec list --count --format toon` SHALL serialize the same structure in Token-Oriented Object Notation.
  - `spec list --count --format text` SHALL output `Total: <total>\n\nWorkspaces:\n  <ws>: <count>` (or `<ws>: <count>` when single workspace filtered).
- **Verification Scenarios**:
  - Mutual exclusivity validation rejecting `--count` with `--summary`.
  - Text mode multi-workspace total and breakdown.
  - Text mode single-workspace filtered output.
  - JSON format output verification.
  - TOON format output verification.
