# Proposal: deprecate-ladybug-store

## Motivation

Ladybug is no longer a backend that specd needs to ship or support as part of
CodeGraph: SQLite is the only integrated backend in use. Keeping Ladybug in the
monorepo retains a native dependency and host-lifecycle workarounds in the main
product, while the implementation itself remains valuable work worth preserving.

## Current behaviour

`@specd/code-graph` registers both `sqlite` and `ladybug` as built-in graph
stores, although SQLite is the default. Ladybug-specific native-process concerns
remain reflected in the CLI graph lifecycle helpers and explicit process-exit
paths. The package also contains Ladybug's implementation, schema, tests, and
specification alongside the SQLite backend.

## Proposed solution

Extract the Ladybug graph-store implementation into the independent
`specd-plugin-graphstore-ladybug` repository/package, preserving its code,
schema, tests, native integration, and Ladybug-specific specification and
verification scenarios without keeping them coupled to the specd monorepo. The
Ladybug specs are recreated in the new repository before their copies are
removed from this repository. The new repository owns the Ladybug spec while
declaring specd's `default`, `code-graph`, and `core` spec workspaces as external
`readOnly` workspaces, so the moved spec retains its existing normative
dependencies without gaining write authority over this repository.

Remove Ladybug from CodeGraph's built-in registry and make SQLite the only
integrated backend. Preserve the registry-driven graph-store composition model,
including additive `graphStoreFactories`, backend-id selection, collision
validation, and external-factory tests, so a future plugin loader can populate
that registry without redesigning provider composition. Remove lifecycle and
signal-handling code that exists only for Ladybug from short-lived CLI graph
commands, while retaining the existing SDK lifecycle helpers and
long-lived-host provider ownership model.

This change does not introduce graph-store plugins, configuration-based store
selection, or runtime loading of the extracted package. A future plugin platform
will define the public integration contract. No backward-compatibility or data
migration is required: there are no known Ladybug users, and any prior graph
state is regenerated by reindexing with SQLite.

## Impact

- `packages/code-graph`: Ladybug infrastructure, tests, package dependency, and
  built-in registration are removed; SQLite remains the only integrated store.
  The graph-store factory registry and its additive registration contract remain.
- `packages/cli`: The graph command lifecycle is simplified by deleting the
  Ladybug-specific wrapper and its signal/forced-exit behaviour.
- `specd-plugin-graphstore-ladybug`: Receives the preserved Ladybug
  implementation, tests, schema, and recreated specs outside this monorepo. It
  is not loaded by specd in this change.
- Existing graph data created by Ladybug is intentionally disposable and is
  recreated by a SQLite reindex.

## Technical context

`CodeGraphProvider` already supports `Symbol.asyncDispose`, so the change must
not describe that as new work. `withOpenGraphProvider` remains necessary for
transient SDK operations and is also used by newer functionality such as
implementation review; it is not removed. Long-lived hosts can retain an
already-open provider and must continue to own its lifecycle.

The current additive `graphStoreFactories` mechanism is an important
composition seam and must remain in place, together with backend-id selection,
duplicate-registration errors, and tests using external factories. It is not
yet a complete public plugin contract because its factory result relies on the
internal `GraphStore` type. The extracted package therefore preserves Ladybug
for later integration and must not be presented as a currently supported
runtime plugin. A future change will evolve the retained registry seam into the
stable public contract, configuration, and plugin-loading model.

SQLite is the source of truth for supported CodeGraph behaviour. Ladybug does
not impose a compatibility target on SQLite; the removal must preserve the
current SQLite-backed public behaviour, including the recently added semantic
symbol-resolution surface.

## Open questions

None for this change. The repository/package is named
`specd-plugin-graphstore-ladybug`; its future conversion into a runtime plugin
is explicitly deferred to the graph-store plugin-platform change. Ladybug's
specification ownership moves with the extracted implementation, while generic
CodeGraph registry requirements remain in this repository.
