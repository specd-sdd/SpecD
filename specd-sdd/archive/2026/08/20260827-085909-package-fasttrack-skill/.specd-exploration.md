# Exploration Context: package-fasttrack-skill

Generated: 2026-08-27

## Problem Statement

`specd-fasttrack` currently exists as a local agent skill at
`.agents/skills/specd-fasttrack/SKILL.md`. The user wants it converted into a
first-class skill distributed by `@specd/skills`, including its template
variables, runtime-specific frontmatter, and installation through every agent
plugin. The existing skill should also be analysed and improved while moving it.

## Agreed Approach

- Create a new change named `package-fasttrack-skill`.
- Move the canonical source to the established skills-template model rather than
  retaining a local Markdown source as the distribution mechanism.
- Add a `specd-fasttrack` skill directory under
  `packages/skills/templates/skills/` containing `SKILL.md.tpl` and
  `skill.meta.json`.
- Let `@specd/skills` render frontmatter and capability-dependent content at
  install time; templates must not contain static frontmatter.
- Ensure the existing Claude, Copilot, Codex, OpenCode, and Agent Skills
  Standard plugins install the new skill and cover it in their install tests.
- Preserve the workflow's useful code-first properties: explicit intent
  exploration, implementation-link tracking, continuous journal updates,
  contract protection, a final audit, and an explicit hand-off to
  `/specd-design`.
- Optimise the prompt during design: remove or reference guidance already
  guaranteed by `shared.md`, reduce repetition, and retain mandatory terminal
  stops and audit obligations.

## Contract and Impact Findings

- `skills:skill-templates-source` requires every standard skill to use a
  `.md.tpl` source plus `skill.meta.json`, and requires runtime frontmatter to
  be injected by `@specd/skills` from structured plugin values.
- It permits capability-aware Handlebars branches for `mcp`, `agents`, and
  `frontmatter`; the skill metadata should declare only the capabilities the
  template actually references or requires.
- It requires shared references to use `@{{sharedFolder}}/shared.md` and forbids
  absolute paths in installed output.
- The graph identifies `skills:skill-templates-source` as MEDIUM risk with
  direct impact on the skills repository, template workflow tests, and Codex,
  Copilot, and Standard plugin installation tests; the affected-spec set also
  includes all five agent-plugin contracts.
- All proposed workspaces are owned. No read-only scope restriction applies.
- The project graph was reindexed on 2026-08-27 before this discovery work.

## Design Guidance

- Determine whether every plugin contract requires a normative delta, or whether
  the existing generic install guarantees are sufficient and only implementation
  tests need updates. Do not expand specifications without a material contract
  change.
- Inspect current `skill.meta.json` files and plugin per-skill frontmatter maps
  to choose exact variable values and tool declarations for `specd-fasttrack`.
- Compare the local fast-track instructions with `shared.md` and existing
  lifecycle templates to centralise common rules without weakening the
  fast-track-specific journal, implementation tracking, spec-contract audit,
  adoption search, blast-radius check, or explicit stop before design.
- Verify discovery includes the new skill in all bundle/list/install/uninstall
  paths, and add focused rendering assertions for frontmatter-capable and
  capability-limited runtimes.

## Alternatives Considered

- Keep `.agents/skills/specd-fasttrack/SKILL.md` as the canonical source:
  rejected because it bypasses package discovery, capability-aware rendering,
  and deterministic multi-runtime installation.
- Add a bespoke plugin distribution path:
  rejected because the existing `SkillRepository` and `ResolveBundle` model is
  explicitly designed to distribute categorized templates to all runtimes.
