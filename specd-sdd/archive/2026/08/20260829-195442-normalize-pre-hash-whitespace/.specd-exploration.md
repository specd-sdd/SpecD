## Motivation & Problem

- Formatting tools (Prettier, editor autofixers, OS line ending converters) frequently alter whitespace, tabs, carriage returns (`\r\n`, `\r`, `\n`), indentation, and line wrapping in artifact files (e.g. `.md`).
- Previously, `applyPreHashCleanup` only applied schema-declared regex substitutions (like `- [x]` -> `- [ ]`), without normalizing remaining whitespace across all artifacts.
- As a result, formatting-only edits changed the SHA-256 hash and caused spurious drift detection (`drifted-pending-review` / `in-progress`).
- Requirement: Universal post-cleanup whitespace normalization must convert any whitespace sequence (`\s+` including ` `, `\t`, `\r\n`, `\r`, `\n`, `\v`, `\f`) to a single space `' '` and trim leading/trailing whitespace across all artifacts, regardless of whether schema `preHashCleanup` rules are declared.

## Approaches Explored & Agreed Strategy

- **Approach 1 (Agreed & Implemented)**: Universal post-cleanup whitespace normalization in `applyPreHashCleanup(content, cleanups)`.
  1. Step 1: Apply all schema-declared regex substitutions in order to preserve line-anchored regex matching (`^`, `$`).
  2. Step 2: Unconditionally apply universal whitespace normalization: `result.replace(/\s+/g, ' ').trim()`.
  3. Ensure `computeArtifactHash` always invokes `applyPreHashCleanup(content, cleanups)` unconditionally.
- **Approach 2 (Rejected)**: Line-by-line trim only — rejected because word-wrapping / soft-wrapping alterations by formatters would still alter line structures and break hash stability.

## Consolidation & Audit Summary

### 1. Root Cause & Solution Summary

- **Root Cause**: Artifact hashing did not normalize whitespace after regex cleanup substitutions, causing external formatters (Prettier, CRLF conversion) to invalidate validated artifact hashes.
- **Solution**: Updated `applyPreHashCleanup` to perform a second pass replacing `\s+` with `' '` and trimming, and updated `computeArtifactHash` to always invoke `applyPreHashCleanup` for all artifacts.

### 8. Spec & Verification Guidance

- **Normative Requirements**:
  - `applyPreHashCleanup` MUST apply schema substitutions first in declaration order, then collapse all whitespace characters (`\s+`) into a single space `' '` and trim leading and trailing whitespace.
  - Content hashing for all artifact completeness and drift detection MUST use `applyPreHashCleanup` for all artifacts, whether `preHashCleanup` is defined in the schema or not.
- **Verification Scenarios**:
  - Verify that modifying newlines (LF vs CRLF) or adding multiple spaces/tabs in a validated artifact does not trigger drift.
  - Verify that regex substitutions with `^`/`$` multiline matching execute correctly before whitespace collapsing.
