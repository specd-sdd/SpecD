## Motivation & Problem

- Before a change has selected specs, fast-track skills need a lightweight, authoritative way to discover the specs injected by resolved project and workspace context patterns.
- `project context` renders context content, while `change context` requires an existing change scope; neither is an ID-only pre-change query.

## Approaches Explored & Agreed Strategy

- Rejected extending `project context`: it would conflate rendering with resolution and risk changing its established contract.
- Rejected adding logic directly in the CLI: pattern matching and active-workspace resolution belong in Core.
- Agreed: add a new Core read-only use case, exposed through SDK and consumed by a thin CLI command: `specd project context-specs`.
- Workspace filter is a list: `ResolveContextSpecsInput.workspaces?: readonly string[]`. The CLI uses repeatable `--workspace <name>` (same pattern as `specs list`), not a positional argument. Omitted/empty selects all configured workspaces.
- Result is provenance-partitioned `{ project, workspaces }` — not a flat `specIds` list — so agents can tell project-level includes from workspace-level includes.

#### Shared helper (`resolveConfiguredContextSpecs`)

- File: `packages/core/src/application/use-cases/_shared/resolve-configured-context-specs.ts`
- Symbols: `resolveConfiguredContextSpecs`, `ConfiguredContextSpecCollector`, `ResolveConfiguredContextSpecsInput`
- Content-free collector API: callers supply `include` / `exclude` callbacks so CompileContext can keep source tracking and protected keys, while the helper owns glob order and `listMatchingSpecs` semantics.
- Order (parity with the previous CompileContext steps 1–4):
  1. project `contextIncludeSpecs` (`listMatchingSpecs(..., 'default', true, ...)`)
  2. project `contextExcludeSpecs`
  3. active-workspace `contextIncludeSpecs` (`listMatchingSpecs(..., workspace, false, ...)`)
  4. active-workspace `contextExcludeSpecs`
- Inactive workspaces are skipped via `activeWorkspaces`.

#### CompileContext migration details

- File: `packages/core/src/application/use-cases/compile-context.ts` / symbol `CompileContext`
- Change `specIds` still register first with `protect: true`; `specDependsOn` still register before patterns.
- `activeWorkspaces` remains `change.workspaces` (change-scoped), not all configured workspaces.
- Optimized project context: helper is still invoked, but project include/exclude arrays are emptied. Workspace patterns still apply. This preserves the old `if (!useOptimizedProjectContext)` skip of steps 1–2 only.
- Exclude callback still refuses to delete protected keys.
- Step 5 (`followDeps` traversal) stays in CompileContext; the helper does not traverse dependencies.

#### `ResolveContextSpecs` use case

- File: `packages/core/src/application/use-cases/resolve-context-specs.ts`
- Symbols: `ResolveContextSpecs`, `ResolveContextSpecsInput`, `ResolveContextSpecsResult`
- Result is `{ project, workspaces }` partitioned by include source. No content, metadata, warnings, or dependency traversal.
- Optional `workspaces?: readonly string[]`: omitted or empty → all configured workspaces; otherwise those names (deduplicated).
- Unknown names throw: one → `Unknown workspace '<name>'`; several → `Unknown workspaces: 'a', 'b'`. Unlike `specs list`, unknown names are not silently ignored.
- Dedup key is `` `${workspace}:${capPath}` ``; provenance is a set of include sources per ID (`'project'` or workspace name). Exclude clears the ID from the effective set.
- Pattern warnings are discarded (`warnings: []`) because this query is ID-only.
- Does not apply CompileContext’s change `specIds` / `specDependsOn` / `followDeps` / optimized-project-context skip. It resolves configured context patterns only.
- Project-level include/exclude still run for the whole project even when `--workspace` only activates workspace-level patterns. That is helper semantics, not a per-workspace catalog filter.

#### Provenance-partitioned result

- Problem: a flat `specIds` list cannot tell whether e.g. `core:workspace` entered via project-level patterns or via the `core` workspace patterns.
- Result shape is now `{ project: string[], workspaces: Record<string, string[]> }` (text nests under `workspaces:`). Renamed away from a brief `global` experiment — `project` matches project-level config patterns.
- `--workspace` only filters which keys appear under `workspaces` / which workspace-level patterns run. It does **not** suppress `project` by default (project-level patterns always apply).
- `--workspaces-only` / `workspacesOnly: true` skips project-level patterns entirely (`project` is `[]`; text omits the `project:` section). Use with `--workspace` for discovery focused on workspace overrides.
- Active workspace keys are always present in `workspaces` (empty arrays / `(none)`), so a filter like `--workspace core` is visible even when that workspace contributed no IDs.
- Helper split: `collector.include/exclude(spec)` is the **all / effective-set** path — identical to the pre-extraction CompileContext callbacks (no source args). Optional `onOperation(op, spec, source)` is provenance-only and does not change collector semantics.
- `CompileContext` only wires `collector` (same bodies as before the source-arg experiment).
- `ResolveContextSpecs` uses `collector` for the effective set and `onOperation` to retain include sources for surviving IDs.
- Dual listing invariant: a spec included by project patterns **and** a workspace's patterns MUST appear in both `project` and `workspaces.<name>`. Covered by `packages/core/test/application/use-cases/resolve-context-specs.spec.ts`.
- Exclude still clears the ID from the effective set entirely (workspace excludes can drop project-included IDs). Surviving IDs keep every include source that contributed them, so dual listing is intentional.
- CLI text output prints `project:` and `workspace:<name>:` sections; json/toon emit the partitioned object.
- Docs updated to match (`docs/cli/*`, `docs/core/use-cases.md`, guide context-compilation note).
- Verified: `@specd/core` `compile-context` vitest suites after restoring the source-free collector.
