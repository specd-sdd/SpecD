## Motivation & Problem

The graph indexer has regressed: indexing is currently being invoked with `--force`, and the isolated worker closes unexpectedly. It is not yet known whether incremental indexing without `--force` is affected. The desired outcome is a stable worker lifecycle for both forced and incremental indexing, with regression coverage.

## Approaches Explored & Agreed Strategy

Agreed strategy:

1. Reproduce forced and incremental indexing while observing the worker lifecycle and IPC boundary.
2. Fix the underlying worker lifecycle or protocol fault rather than masking it.
3. Add regression coverage for both `--force` and non-force execution.

Rejected alternatives:

- Retry automatically when the worker closes: lower implementation cost, but it could conceal a deterministic lifecycle or protocol defect.
- Fall back to in-process indexing: broader blast radius and incompatible with the existing crash-containment/isolation contract unless evidence proves isolation cannot be preserved.
- Patch only the forced path: narrow, but leaves the untested incremental path and shared worker lifecycle vulnerable.
