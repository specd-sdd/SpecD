# Fast-track exploration: context-aware governing specs

`/specd-design` MUST treat `specd changes implementation list fasttrack-context-resolution` and `specd changes implementation review fasttrack-context-resolution --format toon` as the authority for completed work. It MUST evaluate the suggested specs, preserve completed and pending work in formal tasks, investigate omitted edge cases and adoption, and perform downstream impact analysis.

## Motivation & Problem

The packaged `specd-fasttrack` skill discovers specs with generic graph search and reads contracts using `specs show`. It does not use the recently added context-pattern resolution to identify workspace-specific governing specs before modifying files.

## Approaches Explored & Agreed Strategy

- Agreed: resolve configured includes with `project context-specs`; consider its returned IDs as candidate governing specs; infer a candidate's workspace from its `workspace:capability` ID; load relevant contracts with `specs context`.
- Rejected: resolve each edited file with `specs resolve-path`. The user clarified this command is unnecessary because workspace identity is already encoded in the relevant returned spec IDs.
- Rejected: retain `specs show`. It renders source artifacts rather than the compiled, dependency-aware context intended for agents.
