# Exploration Context: unify-graph-project-relative-paths

Generated: 2026-10-12

## Problem Statement

When inspecting the outputs of code graph commands (`specd graph search`, `specd graph hotspots`, `specd graph impact`), there is an asymmetry and inconsistency in how file paths are represented across formats (`text` vs `json`/`toon`) and commands:

1. In `specd graph search --symbols` (JSON/TOON):
   - Locations (`filePath`, `surface`, `location.filePath`, `symbolId`) only return the code-graph canonical path format: `<workspace>:<relativePathFromCodeRoot>` (e.g. `cli:src/commands/graph/search.ts`).
   - There is NO path relative to the project root (`projectRoot`). An external consumer, agent, or IDE script cannot open or read the file directly (e.g. via `cat`, `fs.readFile`, editor, or `view_file`) without custom logic to strip the workspace tag and look up `workspace.codeRoot`.
2. In `specd graph search --files` and `--documents` (JSON/TOON):
   - Returns both canonical `path: "cli:src/program.ts"` and `configRelativePath: "packages/cli/src/program.ts"`.
3. In `specd graph hotspots` (JSON/TOON):
   - Returns canonical `symbol.filePath: "core:src/..."` alongside `displayPath: "packages/core/src/..."` (introducing a third terminology `displayPath`).
4. In `specd graph impact` (JSON/TOON):
   - Returns `canonicalPath`, `displayPath`, and `affectedFiles` (where paths are project-relative strings).
5. In other `specd` commands (`change implementation`, `spec implementation`):
   - The CLI flags and documentation describe these as `project-relative file path` (`--file <path>`).

The user observed that code-graph search appeared relative to the workspace, while other CLI and system commands appeared relative to `cwd` (which coincides with `projectRoot` when running at repository root). The team agreed that the path model should be unified around `projectRelativePath`.

## Approach / Solution Outline

Standardize path representations across all code-graph CLI commands:

1. **Adopt `projectRelativePath` as the unified term and field name:**
   - Anchor: `projectRoot` (the directory containing `specd.yaml`).
   - Formula: `relative(projectRoot, absoluteFilePath)`.
   - Distinct from `canonicalPath` (`<workspace>:<workspaceRelativePath>`).
2. **Expose `projectRelativePath` uniformly in JSON/TOON outputs (NO BACKWARD COMPATIBILITY):**
   - In `graph search --symbols`:
     - Add `projectRelativePath` to symbol declarations and hits (`symbol.projectRelativePath`, `location.projectRelativePath`).
     - Add `projectRelativePath` to `logicalTarget` / `publicBindings`.
   - In `graph search --files` and `--documents`:
     - Replace `configRelativePath` with `projectRelativePath`.
   - In `graph hotspots`:
     - Replace `displayPath` with `projectRelativePath`.
   - In `graph impact`:
     - Replace `displayPath` and `displayTargets` with `projectRelativePath` and `projectRelativeTargets`.
3. **Preserve text mode behavior:**
   - In text mode, `toGraphDisplayPath` already projects to the project root (`packages/cli/src/...`) with `[workspace]` prefix. Keep this human-friendly display.
4. **Update CLI Help and Documentation:**
   - Update `--help` schema documentation in `search.ts`, `hotspots.ts`, `impact.ts`.
   - Update `docs/cli/graph.md` and `docs/guide/code-graph.md`.

## Design Decisions & Agreements Reached

1. **`projectRelativePath` over `configRelativePath`:**
   - Confirmed by user: `projectRelativePath` is conceptually more coherent than `configRelativePath`.
   - Reason: Symmetrical with `projectRoot`. Avoids misleading developers/agents into thinking the path relates to a configuration file.
2. **`projectRelativePath` over `displayPath`:**
   - `displayPath` sounds like UI formatting text rather than a stable relative path for programmatic tool calls.
3. **NO BACKWARD COMPATIBILITY (Explicit user decision):**
   - The user explicitly requested "sin retrocompatibilidad".
   - `configRelativePath` and `displayPath` are completely replaced, not kept as aliases.
4. **Canonical vs Project-Relative duality:**
   - `canonicalPath`: graph identity (`cli:src/foo.ts`).
   - `projectRelativePath`: filesystem repository path (`packages/cli/src/foo.ts`).
   - `workspace`: workspace name (`cli`).
