# SDK development guide — verification follow-up

## Confirmed decisions

- Keep JSON catalogs as the runtime and published artifact format; do not restore generated TypeScript catalogs.
- Generated API topics must not expose repository-internal declaration paths in public metadata, bodies, or search results.
- Unknown-topic candidates for the large SDK catalog remain structured-only; human error messages must stay bounded and direct callers to list, metadata index, and search.
- Repair every confirmed implementation and regression-test gap from the full compliance audit.

## Audit-driven design scope

- Align `cli:guide-sdk` verification scenarios with source-path suppression and the canonical `sdk:classes/ArtifactDag` example.
- Reconcile `guide:errors` with the bounded SDK unknown-topic contract.
- Specify that a normal guide build refreshes the exact package-root JSON assets read by the runtime and published by npm.
- Specify section-bounded search snippets and direct qualified lookup/blank-input rejection in `GetGuideQuery`.
- Add regression coverage for packed artifacts, JSON propagation, snippets, lookup delegation, blank input, and the CLI help example.
- Add the required JSDoc for packaged-catalog loading.

## Impact

The affected surfaces are `@specd/guide` build/runtime/query/search layers, the `guide-sdk` CLI adapter/help output, and their focused tests. The catalog format and collection-qualified addressing remain unchanged.
