## Discrepancies (NEW)

1. MEDIUM - Disabling goes beyond spec and cuts intra-workspace barrel linking. index-code-graph.ts:1229 skips `reExportLinking.link` for any adapter in `disabledPackageResolution`, and :1240 adds to it. Spec says an identity/prepare failure makes the adapter "not provide packageResolution"; it does not say reExportLinking (a separate facet; the TS adapter's link also resolves relative `export * from './x'` barrels) is skipped. Net effect: one bad manifest (identity throw) in any workspace disables TS re-export linking for the whole run, degrading relative barrel/public-binding resolution that has nothing to do with packages. Not tested. Either narrow the skip to prepare failures (link may need prepared data) or document it in the spec.
2. LOW-MEDIUM - Spec gap: prepare failure and link failure disabling the adapter (and the link-only adapter not being listed) are implemented and tested (package-imports.spec.ts:434, 615, 694) but are not stated in spec.md or verify.md; only identity failure is. Add requirement text + scenarios.
3. LOW - Stale baseline verify wording retained in the merged verify: "Package identity built from adapter" (TS adapter "implements getPackageIdentity") and "Adapter without getPackageIdentity skips resolution" (imports "remain unresolved"). The spec now defines `packageResolution.identity` and reports such adapters in `adaptersWithoutPackageResolution`; `getPackageIdentity` no longer exists. Modify those two scenarios (baseline wording contradicts new requirement).
4. LOW - Scoped env fallback: scoped-binding-environment.ts:411-420. In the `targetSymbolId === undefined` branch, if `importedTargets` yields an id but `localSymbolsById`/`findById` find nothing, control falls through to `findTargetCandidates`, i.e. the same-name workspace search the spec forbids ("MUST NOT replace it with a same-name symbol of the importing workspace"). Practically unreachable (ids come from resolved declarations in the same session) but a hydrated/stale id would hit it. Return undefined when an import-bound id is not found.
5. LOW - Over-broad addition fallback: index-code-graph.ts:808-810 triggers on `newFiles.length > 0`, and newFiles includes non-code inputs (docs/specs coverage paths), so adding a markdown file re-extracts every existing code file. Spec says "adds new code files". Conservative, correctness-safe, but costly and not what the requirement text says.
6. INFO - Manifest walk bounds differ: identity() is bounded by `projectRoot` (spec-mandated) while the fingerprint manifest discovery uses `vcsRoot` (index-code-graph.ts:636-637, compute-graph-fingerprint). Fingerprint may be sensitive to manifests identity never reads (over-invalidation only; no correctness issue).
7. INFO - `adaptersWithoutPackageResolution` is deduped by joined language string (index-code-graph.ts:952-956); spec says one entry per adapter. Two adapters with identical language lists would collapse. Unlikely.
