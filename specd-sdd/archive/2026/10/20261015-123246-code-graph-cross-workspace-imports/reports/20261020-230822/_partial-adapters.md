## 3. Discrepancies (spec vs code; either may be wrong)

1. PHP `resolveToPath` returns unindexed target (HIGH-ish, only open prior item). Spec: "MUST NOT fall back to an absolute-path lookup of an unindexed file" and scenario "an unindexed file is never targeted". Code PHP:2283-2285 returns the single candidate regardless of index; tests php-language-adapter.spec.ts:706-719 and :772-785 enshrine it; `resolveFileImport` PHP:1020 pushes it into `fileImports` without `getFileId` (and as an absolute path rather than a workspace-prefixed file id). Possibility A: code wrong (add `getFileId` check, update tests). Possibility B: spec wording is about FS fallback only and `resolveToPath` is a pure mapping (then reword the scenario; note `resolveToPath` has no other consumers in src, only adapter-registry facet listing).
2. PHP `prepare` reads composer.json twice per workspace (`buildPsr4Map` + `getPackageIdentity`, PHP:2144-2150) vs spec "read once (identity reads separately)". Also `analyzeFile` may have pre-read it (PHP ~2213). Wording vs code; no read-count test.
3. TS `matchSpecifier`: spec "longest known package prefix"; code exact first-1/2-segment match (TS:3070-ish `resolvePackageFromSpecifier`). Behaviorally fine; spec wording stricter.
4. TS build-dir mapping: spec generic "a build directory"; code maps only `dist/`. `lib/`, `build/`, `out/` published targets will not map to `src/`. Either broaden code or narrow spec to `dist`.
5. TS `exports` wildcard patterns (`./*`) and nested conditions beyond `import/default/types`: not handled; spec silent on `./*`, consistent with "other conditional resolution unsupported" but a subpath like `pkg/foo` against `"./*"` yields no entry (silent).
6. Python submodule fallback is attempted on any unresolved result (including shared-resolver `ambiguous`), not only "not published by the entry file". Low risk.
7. Go/Python/TS (and PHP) still consult `qualifiedNames.get(imp.specifier)` before package resolution (TS:1420, PY:~949, GO:724). Only PHP supplies a qualified-name facet, so for TS/Py/Go the map is normally empty; spec does not describe this branch. Dead/undocumented path.
8. Go entry assumes package dir = specifier minus module prefix relative to workspace root; if `go.mod` is found above `codeRoot` (bounded walk-up) the directory would be offset. Spec says "under the module's code root"; edge case.
9. TS test naming: PR:424 title "another workspace file is not returned" but asserts a file in the `shared` workspace is returned (title misleading, no defect).
