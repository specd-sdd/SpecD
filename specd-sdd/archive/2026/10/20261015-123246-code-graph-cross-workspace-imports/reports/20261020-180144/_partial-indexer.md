## Discrepancies

D1 (medium). "Test files are not entries ... unless the specifier addresses it": exception missing.

- Spec right / code wrong: spec text and scenario "Test files are not entries" say the candidate is discarded unless addressed explicitly; resolver:77-80 has no such branch, and no test checks it (package-import-resolver.spec.ts:233).
- Code right / spec wrong: ADR-0030 line 41 and docs/code-graph/index.md say "test files are never entries"; an unconditional filter is simpler and prevents tests from becoming public surface. The exception is not defined in the facet contract (the helper has no way to know what "addresses explicitly" means). Spec should drop the clause or define it.

D2 (medium). Closure "MUST NOT scan every file to find importers" vs `additionCandidates` (IC ~L812-813).

- Spec right: any added file makes all existing files seeds, which is a full scan, and it also covers "newly resolvable import" by brute force rather than via the closure.
- Code right: native stores cannot persist a step/relation whose target did not exist (comment at IC ~L809-811), so unresolved imports leave no trace to follow; reconsidering all files is the only sound way for "target workspace newly added". The spec scenario "Newly resolvable import is reconsidered" is satisfiable only this way. Spec should state the conservative exception. Code was not changed by this change.

D3 (low-medium). `facet-absent` startup diagnostic is passed through `recordImportDiagnostic` (IC:935-943) so it increments `total` and `byReason['facet-absent']`, although spec defines `total` as "unresolved package imports excluding external". Spec right: inflates counts with a non-import entry (specifier ''). Code right: spec requires a diagnostic naming language and facet to appear in the output, and `samples` is the only channel; docs/code-graph/index.md lists `facet-absent` among reasons. Fix spec wording (total includes facet notices) or add a separate field.

D4 (low). Package map built before Pass 1 (IC:883) while spec says "Between the passes ... (1) builds the map". Code right: identity needs only manifests, not Pass 1 output, and the test asserts identity < prepare < link < resolve. Spec wording imprecise.

D5 (low). "First adapter to return non-undefined identity for a workspace wins": loop does not stop (IC:884-900). With two adapters (e.g. TS + Python) in one workspace both identities are mapped to it. Code right arguably (a polyglot workspace can have several packages); spec should say "each adapter contributes its own".

D6 (low). `IndexResult.importDiagnostics` counts only files processed in the run (Pass 2 over filesToProcess); in an incremental run the summary is partial. Spec says nothing; document it.

D7 (low). CLI `graph index` text/JSON output does not show `importDiagnostics` (cli/src/commands/graph/index-graph.ts:56,155-200 mention only coverageDiagnostics). Spec says "reported in the indexing output"; satisfied at SDK/IndexResult level only.

D8 (low, risk). scoped-binding-environment `importedTargets` is keyed by name only and the `else if` branch (scoped-binding-environment.ts ~L391-398) applies to any binding fact with `targetName` equal to an imported name and no `targetFilePath`/`targetSymbolId`, regardless of scope. A nested-scope shadow without targetSymbolId would resolve to the import. Same-workspace imports: result unchanged when the import maps to the same symbol that a name search would pick; differs only where a same-name local symbol exists (the intended fix). Shared environment contains no language-specific rules (no ids/extensions); the domain comment in import-declaration.ts mentions TypeScript only in JSDoc.
