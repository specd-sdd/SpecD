# Exploration Context: fix-sqlite-delete-file-variable-limit

Generated: 2026-10-02

## Problem Statement

When indexing or reindexing large generated files such as `packages/guide/src/infrastructure/generated/guides-sdk.ts` (83,292 lines, 4.1 MB) and `guides.ts` (4,908 lines, 469 KB), `specd graph index` crashes with:

```
fatal: too many SQL variables
result: error
code: CLI_ERROR
message: too many SQL variables
exitCode: 3
```

As a temporary workaround, these two files were added to `graph.excludePaths` in `specd.yaml`.

## Root Cause Analysis

- **Location:** [`packages/code-graph/src/infrastructure/sqlite/sqlite-graph-database.ts`](file:///Users/monki/Documents/Proyectos/specd/packages/code-graph/src/infrastructure/sqlite/sqlite-graph-database.ts#L2931-L2949) in private method `deleteFileLocalState(db: SqliteDatabase, filePath: string)`.
- **Mechanism:**

  ```typescript
  private deleteFileLocalState(db: SqliteDatabase, filePath: string): void {
    const symbolIds = (
      db.prepare('SELECT id FROM symbols WHERE file_path = ?').all(filePath) as Array<{
        id: string
      }>
    ).map((row) => row.id)

    if (symbolIds.length > 0) {
      const placeholders = symbolIds.map(() => '?').join(', ')
      db.prepare(
        `DELETE FROM relations WHERE source IN (${placeholders}) OR target IN (${placeholders})`,
      ).run(...symbolIds, ...symbolIds) // <--- CRASH HERE
      db.prepare(`DELETE FROM symbols WHERE id IN (${placeholders})`).run(...symbolIds)
    }

    db.prepare('DELETE FROM relations WHERE source = ? OR target = ?').run(filePath, filePath)
    db.prepare('DELETE FROM file_content_fts WHERE path = ?').run(filePath)
    db.prepare('DELETE FROM files WHERE path = ?').run(filePath)
  }
  ```

- **Trigger:**
  - `guides-sdk.ts` contains > 17,000 symbols.
  - When reindexing or updating that file, `deleteFileLocalState` is invoked (from `upsertFile`, `removeFile`, or `commitBulkIndex`).
  - `symbolIds` receives > 17,000 string IDs.
  - Passing `...symbolIds, ...symbolIds` expands to > 34,000 SQL parameters.
  - SQLite's compile-time limit `SQLITE_MAX_VARIABLE_NUMBER` in modern SQLite is 32,766 (and in older builds 999).
  - Attempting to bind 34,000 parameters causes `better-sqlite3` / SQLite to abort with `too many SQL variables`.

## Proposed Fix

Replace the client-side array gathering and unchunked `IN (${placeholders})` parameter spread with atomic, bounded SQLite subqueries:

```typescript
private deleteFileLocalState(db: SqliteDatabase, filePath: string): void {
  db.prepare(`
    DELETE FROM relations
    WHERE source IN (SELECT id FROM symbols WHERE file_path = ?)
       OR target IN (SELECT id FROM symbols WHERE file_path = ?)
  `).run(filePath, filePath)

  db.prepare('DELETE FROM symbols WHERE file_path = ?').run(filePath)
  db.prepare('DELETE FROM relations WHERE source = ? OR target = ?').run(filePath, filePath)
  db.prepare('DELETE FROM file_content_fts WHERE path = ?').run(filePath)
  db.prepare('DELETE FROM files WHERE path = ?').run(filePath)
}
```

### Advantages of This Fix

1. Reduces parameter count from $O(N)$ (where $N > 17,000$) to exactly 2 parameters (`filePath, filePath`) for `relations` and 1 parameter (`filePath`) for `symbols`.
2. Mathematically impossible to exceed `SQLITE_MAX_VARIABLE_NUMBER`.
3. Much faster: leverages SQLite's internal B-Tree index on `symbols(file_path)` without serializing tens of thousands of string IDs between SQLite C++ engine and V8/Node.js memory.
4. Allows removing the temporary `excludePaths` workaround in `specd.yaml` so `guide` files can be safely indexed.
