# Exploration Context: code-graph-complete-dependency-detection

Generated: 2026-10-13

## Problem Statement

A thorough investigation of `@specd/code-graph` across language adapters, symbol models, reference resolution, and relation derivation revealed several fundamental gaps:

### 1. AST Node Omissions across Language Adapters

#### A. TypeScript (`typescript-language-adapter.ts`)

- **Abstract methods omitted:** `abstract_method_signature` is missing from `targetKinds` (lines 487–504) and the AST switch statement (lines 522–527). In abstract classes like `SpecRepository` (18 abstract methods), only 2 methods (`constructor` and `specsPath`) were indexed in SQLite because they had concrete bodies `{ ... }`. The other 16 abstract methods (`resolveFromPath`, `get`, `list`, `save`, `publish`, etc.) were completely discarded.
- **Interface & abstract class properties omitted:** `property_signature` and `abstract_property_signature` are omitted from `targetKinds`. In interfaces such as `ArtifactMeta`, members like `filename` never reached the SQLite `symbols` table.
- **Function signatures omitted:** `function_signature` (top-level overload signatures and `.d.ts` declarations) is omitted.
- **Enum members omitted:** `enum_declaration` is captured, but individual enum members (`enum_assignment`, `property_identifier`) within the enum body are not extracted as symbols.
- **Field classification:** `field_definition` and `public_field_definition` without function initializers were forced to `SymbolKind.Variable` with `requiresOwner: false` in declaration facts, disconnecting them from their declaring class.

#### B. Go (`go-language-adapter.ts`)

- **Struct fields omitted:** `field_declaration` is completely ignored in `collectSymbols`. Fields of Go structs never enter the code graph.
- **Fragile regex for method receivers:** In lines 400–420, receiver extraction uses a fragile regular expression `^func\s*\(\s*...` against the raw line text instead of querying Tree-sitter's AST nodes (`receiver` / `parameter_list`). This breaks on multiline method signatures and Go generics (e.g. `func (r *Repo[T]) Save(...)`).
- **Missing relations (GitHub Issue #52 debt):** In `go-language-adapter.ts:buildRelations`, `IMPORTS` and `CALLS` relations are completely missing, emitting zero dependency edges for Go files.

#### C. Python (`python-language-adapter.ts`)

- **Class attributes & fields omitted:** Class attributes, dataclass fields, and Protocol attributes (`expression_statement` in `block`) are discarded because `walk()` restricts assignments to `parent.kind === 'module'`.
- **Missing dependencies (GitHub Issue #52 debt):** Calls inside decorators, dataclass type annotations, and certain dynamic call expressions miss relation generation.

#### D. PHP (`php-language-adapter.ts`)

- **Class body members omitted:** `walkClassBody` ignores `const_declaration` and `enum_case`.
- **Properties lack enclosing ownership:** Properties extracted in PHP lack parent linkage in facts.

---

### 2. Defective `parentId` Assignment (`reference-fact-helpers.ts:withEnclosingTypeParents`)

- `withEnclosingTypeParents` only assigns `parentId` when `symbol.kind === SymbolKind.Method`. Properties (`Variable` or `Property`) and traits (`Type`) are completely ignored, leaving `parent_id = NULL` in SQLite.
- It lacks range boundary checking (`endLine`). When an enclosing class ends, `currentOwnerId` is not reset if subsequent top-level symbols follow, risking owner bleeding.

---

### 3. Multiple Signatures & Overloads (Overload Sets)

- **Overload overwriting:** In `typescript-language-adapter.ts`, `TsTypeDeclarationInfo.methodsByName` is a `Record<string, string>` storing a single method ID. Multiple overloads overwrite earlier signatures so only the last one is recorded.
- **Splitting into multiple `LogicalSymbol`s:** In TS classes, signatures (`MemberKind.Signature`) and method bodies (`MemberKind.Method`) split into different `LogicalSymbol` entries instead of being unified under one logical symbol with multiple declaration occurrences.
- **False 'ambiguous' in `resolveSymbolSelector`:** [`resolve-graph-selector.ts:248-265`](file:///Users/monki/Documents/Proyectos/specd/packages/code-graph/src/application/services/resolve-graph-selector.ts#L248-L265) checks `ordered.length > 1`. When querying `ClassName.methodName` on a method with 2 overloads and 1 implementation in the same class/file, `ordered.length === 3` and it returns `status: 'ambiguous'`, even though all three are declarations of the exact same logical method.
- **Incomplete override linking:** `deriveCrossFileOverrideRelations` only links `superMethods.get(name)?.[0]`, dropping connections to other signatures.

---

### 4. GitHub Issue #52 Resolution (SpecD#52)

- Issue #52 tracked incomplete dependency detection across TS, Python, and Go.
- Remaining gaps:
  - Go adapter missing `IMPORTS` and `CALLS` relations in `buildRelations`.
  - TypeScript adapter missing call facts in certain expression positions and dynamic imports.
  - Python adapter missing dataclass field type references and decorator call tracking.

---

### 5. `SymbolKind` Expansion (`Property`) & Ranking / Impact Assessment

- **Closing the semantic gap:** Class, interface, and struct members need a first-class kind. Introducing `SymbolKind.Property = 'property'`:
  - **Hotspots (`compute-hotspots.ts`):** `DEFAULT_HOTSPOT_KINDS = [Class, Method, Function]` excludes properties by default, preventing thousands of fields from flooding architectural hotspots. Meanwhile, abstract methods (as `Method`) gain incoming `OVERRIDES` edges, correctly adding $2 \times \text{overriders}$ to their hierarchy score.
  - **Search Ranking (`sqlite-graph-database.ts`):** Exact matches resolve in Tier 5. Searching `--kinds property` isolates members from module-level `--kinds variable`.
  - **Impact Analysis (`traversal.ts`):** Abstract methods and properties now participate in blast radius calculations (`dependents`) and dependency tracing (`dependencies`).

## Approach & Solution Outline

### 1. Domain & Model (`code-graph:symbol-model`)

- Add `Property: 'property'` to `SymbolKind` enum in `symbol-kind.ts` and `specs/code-graph/symbol-model/spec.md`.
- Formalize overload sets in `LogicalSymbol`: multiple declarations sharing the same canonical identity, owner, and symbol space belong to a single `LogicalSymbol` with `declarations: readonly LogicalDeclarationOccurrence[]`.
- Document that `parentId` on `SymbolNode` applies to both methods and properties/fields.

### 2. Common Language Adapter Contract (`code-graph:language-adapter`)

- Specify that language adapters must extract properties, fields, and abstract methods with valid `parentId`.
- Specify boundary-aware owner tracking in `withEnclosingTypeParents` (checking `symbol.line <= owner.endLine`).
- Unify overload sets so multiple syntactic signatures emit declarations for the same logical symbol.

### 3. TypeScript Adapter (`code-graph:typescript-language-adapter`)

- Add `abstract_method_signature`, `property_signature`, `abstract_property_signature`, `function_signature`, and enum members to `targetKinds`.
- In AST switch:
  - `abstract_method_signature` -> `SymbolKind.Method` with `MemberKind.Signature` / `MemberKind.Method`.
  - `property_signature`, `field_definition` (non-function) -> `SymbolKind.Property` with `MemberKind.Property`.
  - `function_signature` -> `SymbolKind.Function`.
  - `enum_declaration` children -> `SymbolKind.Property` with `parentId = enum.id`.
- Update `TsTypeDeclarationInfo` to store `memberIdsByName: Map<string, string[]>` so overloads are not overwritten.
- Merge overload signatures with their implementation body under the same `LogicalSymbol`.

### 4. Go Adapter (`code-graph:go-language-adapter`)

- Extract `field_declaration` as `SymbolKind.Property` with `parentId = struct.id`.
- Replace regex receiver extraction with Tree-sitter AST queries (`node.field('receiver')` / `parameter_list`).
- Implement `IMPORTS` and `CALLS` relations in `buildRelations` (resolving Issue #52).

### 5. Python Adapter (`code-graph:python-language-adapter`)

- Allow class-level `expression_statement` assignments in class blocks to emit `SymbolKind.Property` with `parentId = class.id`.
- Extract dataclass fields and Protocol attributes as `SymbolKind.Property`.
- Extract decorator calls and dataclass field types into relations (resolving Issue #52).

### 6. PHP Adapter (`code-graph:php-language-adapter`)

- In `walkClassBody`, handle `const_declaration` (as `SymbolKind.Variable` or `Property`) and `enum_case` (as `SymbolKind.Property`).
- Ensure class properties have `parentId` properly assigned.

### 7. Reference Resolution (`code-graph:resolve-symbol-reference`)

- Update `resolvedResult` in `resolve-graph-selector.ts`: if multiple matched declaration symbols belong to the same logical symbol or represent an overload set in the same file/type, resolve cleanly to the primary/implementation match (or bounded candidate) rather than declaring `status: 'ambiguous'`.

### 8. Indexer & Hierarchy Relations (`code-graph:indexer`)

- In `withEnclosingTypeParents`, check `symbol.kind === SymbolKind.Method || symbol.kind === SymbolKind.Property` and verify `symbol.line <= enclosing.endLine`.
- In `deriveCrossFileOverrideRelations`, link `OVERRIDES` relations across all signatures of an overload set.

### 9. Hotspots (`code-graph:hotspots`)

- Maintain `DEFAULT_HOTSPOT_KINDS = [Class, Method, Function]`.
- Verify that restored abstract methods and interface methods correctly calculate hierarchy weights ($3 \times \text{extenders} + 4 \times \text{implementors} + 2 \times \text{overriders}$).

## Design Decisions & Agreements Reached

1. **Brand New Independent Change:** Completely ignore and bypass `code-graph-symbol-semantic-context`. Work proceeds in `code-graph-complete-dependency-detection`.
2. **Add `SymbolKind.Property`:** Introduce `property` into the closed `SymbolKind` enum so properties, fields, and attributes are first-class symbols distinct from module-level variables.
3. **AST-based Go Parsing:** Deprecate and remove regex-based receiver parsing in Go in favor of Tree-sitter AST nodes, supporting generics and multiline signatures.
4. **Overload Set Resolution:** Overloads must not return `status: 'ambiguous'` in `resolveSymbolSelector`. They share a single `LogicalSymbol` with multiple declaration occurrences.
5. **Full Issue #52 Closure:** Integrate all remaining dependency detection debts across TS, Python, and Go into this change.
6. **No Polluting Hotspots:** `DEFAULT_HOTSPOT_KINDS` remains restricted to classes, methods, and functions. Properties are excluded from default hotspots.

---

## Rejected Alternatives

1. **Dynamic AST Runtime Fallback in Selector:** Rejected. Resolving symbols dynamically from AST at query time masks database index incompleteness. The canonical solution is full and correct indexing in the database.
2. **Reusing `code-graph-symbol-semantic-context`:** Rejected per explicit user instruction.
3. **Mapping Properties to `SymbolKind.Variable`:** Rejected because it pollutes variable searches, prevents filtering specifically for properties, and creates ambiguity between top-level variables and class members.
