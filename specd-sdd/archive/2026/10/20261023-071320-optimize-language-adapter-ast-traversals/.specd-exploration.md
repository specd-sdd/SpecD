# Exploration Context: optimize-language-adapter-ast-traversals

Generated: 2026-10-23

## Problem Statement

During code-graph indexing in `../iccms` on branch `feat/code-graph-cross-workspace-imports`, the indexer hung indefinitely around file 500 during the "Analyzing files" phase. The exact same repo indexed successfully on the older branch `feat/suggest-implementation-and-spec-deps`.

Investigation pinpointed the exact file triggering the freeze:
`../iccms/app/controllers/default/articles_importers_controller.php`

- 12,223 lines of code
- 158,193 AST nodes
- 152 methods in a single class

The freeze was caused by commit `2d4423557` ("feat: implement reference resolution logic for cross-workspace and project dependencies"), which added member semantics extraction (`phpMemberSemantics` and `pythonMemberSemantics`). In both PHP and Python adapters, member semantics resolution executes recursive $O(M \times N)$ AST traversals (where $M$ is the number of methods/members and $N$ is the number of AST nodes in the class or file).

In `articles_importers_controller.php`, $152 \times 158,193 \approx 24,045,336$ NAPI AST node visits occurred. In combination with NAPI heap retention and garbage collector pressure, the Node.js process spiked past 5.0 GB RSS and locked up at 100% CPU.

## Root Cause Details

### 1. PHP Adapter (`packages/code-graph/src/infrastructure/tree-sitter/php-language-adapter.ts`)

- **Location:** Lines 394–413 (`phpMemberSemantics`) and 1539–1600 (`collectPhpTypeInfo`).
- **Mechanism:** For each method in a class, `phpMemberSemantics(symbol, ownerNode)` calls `collectPhpTypeInfo(ownerNode)`.
- `collectPhpTypeInfo` defines a recursive `collect(node)` function that visits all descendant nodes of `ownerNode` (the entire class).
- For a class with 152 methods and 158k nodes, `collect(ownerNode)` traverses the entire 158k-node class body 152 times.
- Furthermore, `ownerNode.child(idx)` calls into `@ast-grep/napi`, allocating C++ / JS wrapper handles that pile up in memory.

### 2. Python Adapter (`packages/code-graph/src/infrastructure/tree-sitter/python-language-adapter.ts`)

- **Location:** Lines 235–264 (`pythonMemberSemantics`).
- **Mechanism:** For every method symbol, `pythonMemberSemantics` calls `collectByKind(classNode, ['function_definition', 'async_function_definition'])`.
- If a class has 100 methods, it runs a full recursive walk of the entire class AST 100 times.
- If `classNode` is not passed or resolved, it falls back to `collectByKind(root, ['class_definition'])`, walking the _entire file_ AST.
- Additionally, `indexLanguageFile` in the Python adapter runs 9 separate full-file AST walks (`collectByKind(root, ...)`).

### 3. Cross-Adapter Scope Shadowing & Helper Bottlenecks

- **Shadowing checks:**
  - `isPythonShadowedByEnclosingScope` (`python-language-adapter.ts#L144`): on every reference, walks enclosing function bodies searching for parameter names / assignments.
  - `isShadowedByEnclosingScope` (`typescript-language-adapter.ts#L244`): walks up the AST and re-searches scope nodes on every identifier.
  - `isGoShadowedByEnclosingScope` (`go-language-adapter.ts#L106`): repeatedly walks AST blocks per reference.
- **Callable containment:**
  - `findContainingCallableSymbol` (`packages/code-graph/src/infrastructure/tree-sitter/reference-fact-helpers.ts#L249`): filters and sorts all `symbols` in the file for _every single call expression reference_. For a file with 1,000 calls and 500 symbols, this executes 500,000 comparisons and array allocations.

## Benchmark & Verification Results

A standalone verification test in scratch isolated `articles_importers_controller.php`:

- **Current unoptimized code:** Process froze / exceeded 40s with CPU pegged at 100% and memory escalating to >5 GB.
- **Optimized approach:** Visiting only immediate `declaration_list` children of the class once to map member declarations:
  - Total processing time: **1.5 seconds**.
  - Memory consumption: Normal (<150 MB).
  - All 152 methods correctly extracted with accurate member semantics.

## Approach / Solution Outline

1. **PHP Language Adapter Optimization:**
   - Instead of calling recursive `collectPhpTypeInfo(ownerNode)` for every method, inspect the class node's `declaration_list` directly or build a per-class member declaration cache in a single pass.
   - Immediate children iteration: `class_declaration` -> `declaration_list` -> direct children (`method_declaration`).
   - Extract visibility (`public`/`protected`/`private`), `static`, and `abstract` modifiers from immediate child nodes without recursive descent into method bodies.

2. **Python Language Adapter Optimization:**
   - In `pythonMemberSemantics`, iterate direct children of `class_definition -> block` rather than calling `collectByKind(classNode, ...)` recursively.
   - Memoize / cache class members during symbol collection so `pythonMemberSemantics` does $O(1)$ lookups.
   - Avoid falling back to full-file `collectByKind(root, ['class_definition'])`.

3. **General Scope Shadowing & Fact Helpers Optimization:**
   - In `findContainingCallableSymbol`: sort symbols once per file by range (or maintain an interval tree/sorted list) and use binary search ($O(\log S)$ instead of $O(S)$ filter+sort per call).
   - In shadowing checks: pre-calculate local scope variables when entering a function AST node rather than re-scanning upward on every identifier reference.

## Design Decisions & Agreements

- **Strict backward compatibility:** Member semantics output (`visibility`, `isStatic`, `isAbstract`, etc.) must remain identical to current output for all existing test cases.
- **Memory safety:** Avoid unnecessary NAPI AST node object creation and retention. Do not traverse into function/method bodies when resolving class-level member semantics.
- **Single-pass indexing preference:** Class member discovery should be performed once per class node rather than once per member symbol.
