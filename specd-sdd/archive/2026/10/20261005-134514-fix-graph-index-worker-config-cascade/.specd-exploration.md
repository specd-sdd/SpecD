# Exploration — fix-graph-index-worker-config-cascade

## Problem statement

`specd graph index` runs indexing inside an isolated child worker (`runIsolatedGraphIndex`).
The parent resolves graph context (including config discovery with layered cascade merge),
but only forwards a resolved `configFilePath: string` to the child. The child reloads with
`openSpecdHost({ configPath })` = **forced mode** = closed `extends` chain, **no
`specd.local.yaml` / `specd.local.*.yaml` / `specd.*.yaml` sibling merge**.

Consequence: when the CLI is invoked **without** `--config`, the parent locks/derives
storage from the **merged** config while the child indexes with the **unmerged** config.
Parent and child disagree on effective `projectRoot` / `workspaces` / `allowedPaths` /
`excludePaths` and on which store generation is written.

   _parent_ autodiscovers, the _child_ does not; child receives already-resolved input.

## Approach / solution outline (agreed, not yet implemented)

Propagate the **resolution mode**, not just the resolved file. Split the worker context
descriptor:

```ts
export type CliGraphIndexContextDescriptor =
  | { mode: 'forced'; configFilePath: string } // explicit --config
  | { mode: 'discovered'; startDir: string } // auto-discovery, replay in child
  | { mode: 'bootstrap'; projectRoot: string; vcsRoot: string } // no specd.yaml
```

Child (`packages/cli/src/graph-index-task.ts`, `runGraphIndexTask`):

- `forced` → `openSpecdHost({ configPath, options: { kernel } })` (current behavior, keep).
- `discovered` → `openSpecdHost({ startDir, options: { kernel } })` (same cascade as parent).
- `bootstrap` → `createSdkContext(createBootstrapGraphConfig(...))` (unchanged).

Parent (`packages/cli/src/commands/graph/resolve-graph-cli-context.ts` + `index-graph.ts`):

- `--config` → `{ mode: 'forced', configFilePath }`.
- no flags + `resolveConfigPath() !== null` → `{ mode: 'discovered', startDir: process.cwd() }`
  (capture `cwd` in the parent at resolve time; do not rely on inherited child `cwd`).
- `--path` / no config found → `bootstrap` as today.

`startDir` is a plain absolute-path string: JSON-serializable, passes
`assertGraphIndexJsonValue`. Strict failure if child discovery finds nothing after parent
found something (TOCTOU) — do not silently fall back to bootstrap.

## Design decisions

- Replay discovery in the child (`openSpecdHost({ startDir })`) rather than serializing
  the parent's resolved `SpecdConfig` over IPC. Reason: `SpecdConfig` is not JSON-safe
  (workspace `Map`s, absolutized paths, warnings, bound kernel) and would duplicate
  loader logic on both sides of the IPC boundary.
- Keep explicit `--config` as true forced mode (no locals). That matches documented
  `FsConfigLoader` semantics and user expectation of an exact file.
- Bootstrap path unchanged (`createBootstrapGraphConfig` + `createSdkContext`).
- `storageRoot` for the isolated-run lock keeps coming from the parent merged config;
  after the fix the child resolves the same project, so lock and content agree.

## Rejected alternatives

- **Serialize full `SpecdConfig` parent→child and use `createSdkContext` directly.**
  Rejected: not JSON-serializable, brittle, duplicates loader/kernel wiring.
- **Child always discovers from its own `cwd` with no `startDir` passed.**
  Rejected: works in happy path but implicit; breaks explicit `--config`, `--path`,
  test mocks, and any future `cwd` divergence; TOCTOU without an anchor.
- **Pass active chain (file list) and load a multi-file forced cascade.**
  Rejected: requires new loader support for explicit chains; larger change than
  replaying `startDir` through the existing `openSpecdHost` input.
