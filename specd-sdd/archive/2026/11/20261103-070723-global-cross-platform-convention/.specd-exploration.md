## Problem statement

## Planned content of `_global/cross-platform` (what + how)

- **Paths:** `node:path` (`join`, `resolve`, `sep`); no hardcoded `/` or `\`; logical IDs/stored paths normalized to `/`; `path.win32`/`path.posix` only deliberately; `pathToFileURL`/`fileURLToPath` for file URLs.
- **Case sensitivity:** never rely on it when comparing/resolving paths.
- **Windows reserved names / invalid chars:** `CON`, `NUL`, `COM1`, `:`, `<>"|?*`, trailing dot/space in segments that reach disk (see `core:spec-id-format`).
- **Line endings / encoding:** CRLF, CR, LF equivalent for hashes, comparisons, parsing, marker files; write UTF-8 without BOM; tolerate BOM on read.
- **Processes / shell:** prefer `spawn`/`execFile` without shell; handle `*.cmd`/`.bat` (shell required, `windowsHide`); no POSIX-only builtins; quoting/expansion differences (`%VAR%` vs `$VAR`) (see `core:hook-runner-port`).
- **Permissions / symlinks:** don't rely on chmod bits; symlinks optional with fallback.
- **Long paths / file locking:** Windows MAX_PATH; open files cannot be deleted/renamed; atomic write (tmp + rename) with retries.
- **Dirs / env:** `os.homedir()`, `os.tmpdir()`, `os.EOL`; no hardcoded `/tmp` or `~`; env var names case-insensitive on Windows.
- **Enforcement pointers:** tests (`_global/testing`) and CI matrix (`_global/continuous-integration`).
