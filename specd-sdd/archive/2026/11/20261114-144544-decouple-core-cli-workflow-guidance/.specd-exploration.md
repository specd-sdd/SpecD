# Exploration Context: decouple-core-cli-workflow-guidance

## Problem statement

In the preceding change `decouple-core-cli-error-hints` (commit `77f5da727`), `@specd/core` error and validation messages were decoupled from CLI flags and command strings, and `@specd/cli` introduced centralized hint resolution in `packages/cli/src/error-hints.ts`. However, non-error workflow guidance and status/blocker projections in `@specd/core` were explicitly deferred to a separate change (`specd-sdd/archive/2026/11/20261114-104525-decouple-core-cli-error-hints/proposal.md#L117-L121`).

Currently, `@specd/core` still embeds CLI commands, slash commands, and CLI flags directly in read/projection models:

1. `packages/core/src/application/services/lifecycle-guidance.ts` (`resolveLifecycleCommand`, `phaseCommand`, `resolveLifecycleNextAction`) returns literal CLI commands (`'specd changes approve spec'`, `'specd changes approve signoff'`, `'specd change archive'`) and agent slash commands (`'/specd-design'`, `'/specd-verify'`, `'/specd-implement'`, `'/specd-archive'`) in `LifecycleNextAction.command` / `NextAction.command`.
2. `packages/core/src/application/use-cases/get-status.ts` constructs `bypassFlag: '--skip-checks <checkId>'` on `Blocker` (lines 1027, 1052) and formats `Use ${bypass} to archive anyway.` into `nextAction.reason` in `_nextActionAfterArchiveOverlap` (lines 1076-1080), plus `command: '/specd-archive'` (line 1085).
3. `packages/core/src/domain/services/lifecycle-verdict.ts` generates `bypassFlag: '--skip-checks ${check.id}'` in `blockersFromFailedChecks` (line 972) and strips `--` / `--skip-checks ` in `isBypassFlagActive` (lines 25-32).
4. `packages/core/src/application/use-cases/reconcile-change-validity.ts` (line 487), `packages/core/src/domain/services/change-validity.ts` (line 544), and `packages/core/src/domain/checks/verification-current.ts` (lines 33, 42) emit `details: { command: 'specd changes verification start <name>' }` and `{ command: 'specd changes status <name>' }`.

This couples `@specd/core` to CLI/agent-slash-command syntax and makes it awkward for `@specd/mcp` or other hosts (SDK, IDE) to adapt workflow guidance and bypasses to their own interaction model.

## Approach / solution outline

Apply the same host-neutral core + delivery-presenter architecture used in `decouple-core-cli-error-hints`, adapted for non-error projection/status models:

1. **Structured semantic intents for lifecycle & verification guidance (replacing `command: string` in core):**
   - Replace literal `command` strings in `LifecycleNextAction` / `NextAction` and `details.command` (in `change-validity.ts`, `reconcile-change-validity.ts`, `verification-current.ts`) with typed, host-neutral semantic intents (e.g., `LifecycleActionIntent` / `GuidanceIntent` with `kind`: `'design' | 'implement' | 'verify' | 'archive' | 'approve' | 'verification-start' | 'refresh-status'` and structured parameters like `changeName`, `gate: 'spec' | 'signoff'`).
   - Delivery adapters interpret the intent into their own idiom:
     - `@specd/cli`: a centralized presenter (e.g., `guidance-presenter.ts`, parallel to `error-hints.ts`) translates intents to CLI commands (`specd changes approve spec <name>`) or slash commands (`/specd-design`) and can retain `command` in CLI JSON/TOON output if backward compatibility is needed.
     - `@specd/mcp` / other hosts: translate intents to MCP tool calls + arguments (e.g., `specd_change_approve` with `{ name, gate: 'spec' }`) or host-specific prompt guidance.

2. **Structured bypass capability for blockers (replacing `bypassFlag` and prose in `reason`):**
   - Remove `bypassFlag` (`'--skip-checks <checkId>'`) from `@specd/core` (`Blocker`, `LifecycleBlocker`, `lifecycle-verdict.ts`, `get-status.ts`). `Blocker` already carries `isSkippable: boolean` and `checkId?: string`, or can expose a structured `bypass` descriptor (`{ kind: 'skip-check'; checkId: string }`, extensible to `force` / `skip-hook-phase` if needed).
   - Update `isBypassFlagActive` / `bypassFlags` in `lifecycle-verdict.ts` to operate on host-neutral check IDs / bypass tokens rather than parsing `--skip-checks `.
   - Keep `_nextActionAfterArchiveOverlap` `reason` in `get-status.ts` host-neutral (`overlap.message`, without `Use --skip-checks ... to archive anyway.`).
   - Delivery adapters project the bypass:
     - `@specd/cli`: `status.ts` and `transition.ts` render `bypass: --skip-checks <checkId>` from `checkId` / `bypass` (and CLI JSON/TOON can optionally keep `bypassFlag` at the CLI boundary if required).
     - `@specd/mcp`: maps `{ kind: 'skip-check', checkId }` to `skipChecks: [checkId]` on MCP tool calls.
