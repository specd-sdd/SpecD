# Partial audit: Go adapter + shared specs (go-selectors-python-reexports)

Scope: code-graph:go-language-adapter, code-graph:language-adapter, code-graph:symbol-model (merged previews). Read-only. Probes run with throwaway vitest scripts in the scratchpad (no repo files modified).

Paths: A = packages/code-graph/src/infrastructure/tree-sitter/go-language-adapter.ts, T = packages/code-graph/test/infrastructure/tree-sitter/go-language-adapter.spec.ts (qualified-selectors describe at L1879-2363), C = test/infrastructure/tree-sitter/language-adapter-conformance.spec.ts (appended describes, ~L1711+), I = test/integration/go-selectors-python-reexports.spec.ts, Q = test/domain/value-objects/qualified-reference-fact.spec.ts, P = test/application/use-cases/index-code-graph.package-imports.languages.spec.ts.

## Verdict summary

Core happy paths (call/construct/type facts, resolveImports qualifiedTargets, buildRelations, no name search, unexported stays unresolved, no step without local binding, cross-workspace) are IMPLEMENTED and TESTED. Real defects found:

1. (code vs spec, MEDIUM) Shadowing detection is incomplete and position-insensitive (A:121-208, 1319-1368). Probed:
   - Emits a fact (so can create a FALSE edge if `auth` is an imported namespace) when the qualifier is shadowed by: named result `func f() (auth int)`; grouped local `var ( auth int )` (tree-sitter var*spec_list not walked, A:159-167); `for *, auth := range`; `if auth := g(); ...`; `switch auth := v.(type)`.
   - Suppresses a legitimate fact (FALSE negative) when the shadowing declaration comes AFTER the use in the same block (`auth.A(); auth := 1`), because block bound-names are collected for the whole block, and for a parameter named like the package used in a parameter TYPE (`func f(auth int, x auth.User)`, Go scopes params to the body).
   - Local type declarations (`type auth struct{}`) are not treated as bindings.
     Spec text (go "Package identity..." and verify "Shadowing applies to every fact kind") lists "parameter, result, receiver, local variable, or local declaration". Code covers parameter, receiver, `:=`, plain `var`/`const` only. Fix is in code (spec is right).
2. (spec/code gap, MEDIUM) Resolution step is lost whenever the namespace name differs from the import's local binding name. goNamespaceBindings looks up the file-scope Namespace local binding by the NAMESPACE name (A:1251-1256) but the binding is created under `imp.localName` = last path segment or alias (A:958-969, 1708-1713). Probe: `import "github.com/acme/go-auth"` (package auth) and `.../auth/v2` resolve the target (qualifiedTargets=1, fileImports=1) but produce 0 steps and the local binding `go-auth` / `v2` keeps targetId undefined; plain `.../auth` gives 1 step. This is spec-literal ("namespace without such a binding contributes no step") but defeats the purpose for exactly the declared-name/versioned cases. Either the spec should say the step is anchored on the import's own local binding (code should look up by `imp.localName`/specifier), or accept. No test asserts steps for these cases.
3. (spec wording) language-adapter "Qualified reference resolution" says missing `sourceSymbolId` blocks only `call`/`construct`; code (A:1199) blocks all three kinds (a USES_TYPE relation cannot exist without a source anyway). Spec should say "any kind". Test only covers call/construct.
4. (undocumented behaviour) Two resolved imports yielding the same namespace name are both dropped (A:1246-1249). Not in spec (Go compile error anyway); harmless but unspecified/untested.

## Contradictions with project-wide specs (default:\_global/\*)

None found. conventions: explicit return types, named exports, readonly, kebab-case file (qualified-reference-fact.ts) satisfied; no `any` observed. Minor testing-spec nits: I (integration/go-selectors-python-reexports.spec.ts) does not mirror a src file name (test-naming/mirroring rule), though integration/ already hosts similar files; descriptions follow "given/when/then" for T and I; test "Q ... draft without the collection" is not a meaningful assertion. Nothing in the three change specs contradicts direct deps (code-graph:language-adapter <-> symbol-model are consistent; go spec's "Qualified reference resolution" reference and symbol-model fact definition match).

## Missing / weak tests (actionable)

1. Shadow tests for: named result, receiver, grouped `var (...)`, `range`/`if` init, type-switch, local type; and the use-before-declare ordering (and probably decide intended semantics).
2. Step assertion for declared-name and /v2 namespaces (would expose defect 2) and for explicit alias.
3. Dedup test: repeated `auth.NewUser()` and qualified-vs-callFact produce one CALLS.
4. Test that `auth.User()` conversion (call kind, value space) does not resolve to a type, and that a construct/type fact does not resolve to a function (symbol-space argument).
5. C "last-segment fallback reads no files": make the target package indexed-but-undeclared or assert a positive resolution with readFileSync spy.
6. Q "plain data" / "absent collection": use a real adapter-produced registered analysis and JSON roundtrip.
7. Dot/blank import test lacks a positive control (non-dot import of same package resolving).
8. Missing-source for kind `type` untested (code blocks it).
9. Generic composite literal `auth.Box[int]{}` (construct via generic_type) untested.
10. I (integration) asserts only relation kinds between app:main.go and auth: targets, not specific target IDs (T covers IDs).
