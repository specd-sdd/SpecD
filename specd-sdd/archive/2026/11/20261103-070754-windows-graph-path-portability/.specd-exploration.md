## Motivation & Problem

- Windows CI (`https://github.com/specd-sdd/SpecD/actions/runs/41575757097`) fails 5 `@specd/code-graph` tests while Ubuntu/macOS pass.
- Failures: (1) `explain-graph-path` drive letter absolutism on win32; (2) `index-code-graph.failed-targets` unreadable-file hashing via chmod; (3–5) PHP `require`/`include` relative IMPORTS empty because `path.resolve` emits `\` while graph keys use `/`.
- Goal: introduce a shared portable graph-path helper, adopt it at FS-resolve call sites that become graph keys, and cover Windows/POSIX/drive/backslash/workspace-prefixed cases with tests so adapters (PHP first; TS/Python latent) stay separator-safe.

## Approaches Explored & Agreed Strategy

- **Chosen**: Shared portable path helper (`toPortableGraphPath` / `resolveGraphPath`-style) applied after any FS `path.resolve` used as a graph key; comprehensive unit tests for Windows, POSIX, drive letters, backslashes, workspace-prefixed paths; fix explain-graph-path win32 drive handling and failed-targets Windows unreadable simulation separately as related CI blockers.
- **Rejected — test-only skips/platform guards for path identity**: Masks real Windows path bugs; violates cross-platform testing contract. (`it.skipIf(win32)` remains only for chmod unreadability, a known OS noop — same precedent as size-limit — not for separator/drive/UNC behaviour.)
- **Rejected — large new path abstraction layer across the monorepo**: Over-scoped for unblocking CI; helper + call-site adoption is enough.
