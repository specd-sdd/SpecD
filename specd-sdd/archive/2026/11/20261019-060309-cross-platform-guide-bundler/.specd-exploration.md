# Exploration Context: cross-platform-guide-bundler

Generated: 2026-10-19

## Problem Statement

In the GitHub Actions CI run on `windows-latest` (job `113755937415`, run `37911028819`), the check failed during `pnpm test` for `@specd/guide`:

- In the build step (`pnpm build` -> `@specd/guide:build` -> `tsx scripts/bundle-guides.ts`), TypeDoc emits the error:
  `[error] The glob "D:\a\SpecD\SpecD\packages\sdk\src\index.ts" escapes a non-special character. Glob inputs to TypeDoc may not use Windows path separators (\), try replacing with posix path separators (/)`
- TypeDoc rejects all entrypoints because they contain Windows backslashes (`\`). It logs warnings that no entry points were provided and exits without generating symbols.
- As a result, `packages/guide/generated/guides-sdk.json` is generated without any API reflection topics (0 generated topics instead of the expected ~1300+).
- During `pnpm test`, 6 integration tests in `packages/guide/test/integration/sdk-catalog.spec.ts` fail:
  - Line 164: `expect(guides.withheld?.generatedTopics).toBe(...)` received `undefined`.
  - Line 174: `expect(all.pagination.total).toBeGreaterThan(documents.pagination.total)` received `21` vs `21`.
  - Line 181: `expect(guides.pagination.total).toBeGreaterThan(0)` received `0`.
  - Line 215: Pagination topic ordering mismatch for collection `core`.
  - Line 238: `GuideTopicNotFoundError: Guide topic 'sdk:interfaces/Kernel' not found.`
  - Line 317: `expect(sdkCount).toBeGreaterThan(userCount * 10)` received `21` vs `220`.

The job passed on `ubuntu-latest` and `macos-latest` because POSIX path separators (`/`) are native on those platforms.

## User Directives & Constraints

- Explicit user requirement: "dicho esto si luego se crean nombres de topics de alguna forma, deben estar normalizados en todos los sistemas. Esto debe quedar reflejado en specs".
- All topic names (`topic`), source paths (`sourcePath`), and references across platforms must be strictly normalized to POSIX format (`/`).
- This cross-platform normalization invariant must be formally reflected as requirements and scenarios in `guide:bundle-guides`.

## Approach / Solution Outline

1. **TypeDoc Entry Point Normalization**:
   In `packages/guide/scripts/sdk-api-generator.ts`, normalize `entryPath` to POSIX path format (e.g. replacing `\` with `/`) before passing it in `entryPoints: [entryPath]` to `typedoc.Application.bootstrapWithPlugins`.
2. **Topic Name and Path Invariants**:
   Audit all places where topic identifiers, relative paths, and package roots are created or compared across `packages/guide/scripts/` (`sdk-api-generator.ts`, `guide-bundler.ts`, `bundle-guides.ts`):
   - In `sdk-api-generator.ts`: `resolveSourcePath`, `topic` assembly (`${spec.directory}/${reflection.name}`), `packageRoot` path prefix comparisons (`${packageRoot}${path.sep}`).
   - Ensure all emitted topic identifiers use forward slashes (`/`) regardless of the host OS separator.
3. **Spec Updates (`guide:bundle-guides`)**:
   Add requirement/scenarios to `specs/guide/bundle-guides.spec.md` specifying:
   - TypeDoc entrypoint paths are normalized to POSIX format so that Windows path separators do not trigger glob escape errors.
   - Emitted guide topic identifiers and source paths must always use forward slashes (`/`), ensuring deterministic catalog output across all platforms (Windows, Linux, macOS).
