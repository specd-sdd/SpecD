## Problem statement

The `Change` domain entity incorrectly relies on parsing the `history` array to find the `type: 'created'` event in order to determine its schema (`schemaName` and `schemaVersion`). The root `manifest.schema` object exists but is bypassed. This is conceptually flawed; the schema should be the source of truth and hydrated directly upon change creation without traversing the event history.

## Approach / solution outline

- Modify `ChangeProps` in `packages/core/src/domain/entities/change.ts` to include `schemaName` and `schemaVersion` fields.
- Update the `Change` class constructor to initialize its schema fields from `ChangeProps`, rather than dynamically deriving them via `this._history.find(e => e.type === 'created')`.
- Ensure that `packages/core/src/infrastructure/fs/change-repository.ts` reads the top-level `schema.name` and `schema.version` from the raw manifest JSON and passes them to `new Change()`.
- Ensure that `changeToManifest` reconstructs the manifest's top-level `schema` object from the `Change` entity's own schema properties, instead of searching the history.
- Update `create-change.ts` and `manifest-change-loader.ts` to supply `schemaName` and `schemaVersion` during `Change` instantiation.

- **Domain**: `packages/core/src/domain/entities/change.ts` and its tests
