# Exploration Context: optimize-guide-bundle-storage

Generated: 2026-09-29

## 1. Problem Statement

The generated guide catalog file (`packages/guide/src/infrastructure/generated/guides.ts`) currently weighs ~1.3 MB. This occurs because the bundling script (`packages/guide/scripts/bundle-guides.ts`) duplicates Markdown text multiple times:

1. Full guide body stored in `GuideTopic.content`.
2. Every section in `GuideTopic.outline` stores its full section text in `GuideSection.content`.
3. Due to Markdown header hierarchy, higher-level sections (H1/H2) span across child sub-sections (H3/H4), causing the text of child sections to be duplicated 2, 3, or more times within the compiled bundle.

This causes unnecessary bundle bloat, high memory footprint, and slow compilation/loading.

## 2. Approach / Solution Outline

- **Build time (`bundle-guides.ts`)**:
  - Pre-calculate exact character offsets (`startOffset`, `endOffset`) or line bounds within `cleanBody` for each section during compilation.
  - Do NOT serialize `content` inside each `outline` item in `GUIDES_CATALOG`.
  - Store lightweight section descriptors (`index`, `heading`, `level`, `startLine`, `endLine`, `lines`, `startOffset`, `endOffset`).
- **Runtime on-demand extraction (`@specd/guide`)**:
  - Provide a pure helper/method (e.g., `extractSectionContent(content, section)` or `content.slice(startOffset, endOffset)`).
  - MiniSearch indexing (`MiniSearchGuideEngineAdapter`): extracts section content on the fly while building the in-memory search index.
  - Section retrieval query (`GetGuideSectionQuery`): resolves the section and populates `content` on the fly from the parent `GuideTopic.content`.
  - Outline / metadata inspection (`GetGuideOutlineQuery` / CLI `--meta`): keeps outline lightweight without holding redundant string copies.

## 5. Design Decisions

- Offsets: Use pre-calculated character indices (`startOffset`, `endOffset`) alongside line numbers for $O(1)$ instant string slicing (`topic.content.slice(section.startOffset, section.endOffset)`).
- API Compatibility: Keep `GuideSection.content` populated when `getGuideSection()` is called so public consumers and CLI do not break.
- Outline payload: Outlines in catalog/metadata only store the structural metadata (index, heading, level, line spans, offsets), avoiding megabytes of redundant strings.

## 6. Agreements Reached

- Precalculate offsets at build time instead of parsing markdown at runtime.
- Slice content on the fly when adding to MiniSearch index and when querying a section by index/heading.

## 7. Steps / Plan Defined

1. Update domain models / types if needed (`startOffset`, `endOffset`, optional or dynamic `content` in outline).
2. Update `bundle-guides.ts` to calculate `startOffset`/`endOffset` and omit `content` from `outline` items in `GUIDES_CATALOG`.
3. Update `GetGuideSectionQuery` to slice `content` dynamically from `GuideTopic.content`.
4. Update `MiniSearchGuideEngineAdapter` to slice `content` dynamically during index construction.
5. Re-run `bundle-guides.ts` to regenerate `guides.ts` and verify size reduction.
6. Update and run test suites across `packages/guide` and CLI.

## 8. Rejected Alternatives

- Runtime regex / markdown parsing: Discarded because character offsets can be pre-calculated at build time with 0 runtime parsing overhead.

## 9. Key Codebase Observations

- `extractSections` in `bundle-guides.ts` already knows the line boundaries (`startLine`, `endLine`) and line slices. It can easily compute character offsets in `cleanBody`.
