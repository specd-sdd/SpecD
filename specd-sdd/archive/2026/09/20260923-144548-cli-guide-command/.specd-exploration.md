# Exploration Context: cli-guide-command

Generated: 2026-09-23

## Problem Statement

When `specd` is used in external repositories (e.g. applications, monorepos, backend/frontend projects), developers and AI agents do not have access to the `docs/` tree from the specd repository.
Furthermore:

1. Public LLMs have no pre-training on `specd` conventions, schemas, or workflow rules.
2. The MCP package (`packages/mcp`) is currently an unpopulated stub (`// @specd/mcp`).
3. CLI commands like `specd schema show` or `specd config show` provide raw schema dumps or resolved configurations, but do not provide conceptual explanations, guides, or usage recipes.
4. Existing documentation has significant structural and content issues:
   - **Internal vs. User bleed:** In `docs/guide/`, developer-internal documentation is mixed in (e.g., `skills-template-rendering.md` describes Handlebars `.md.tpl` compilation inside `packages/skills`).
   - **User documentation outside guide:** Critical user-facing documentation is buried in examples or reference folders (e.g., `docs/schemas/examples/delta-files.md` is the only complete guide for writing `.delta.yaml` files; schema templates are only in `packages/schema-std/templates/`).
   - **Outdated / Contradictory information:** `docs/config/config-reference.md` states that `specd.local.yaml` is never merged or layered, directly contradicting `docs/guide/configuration.md` and the actual layered config cascade feature implemented in `packages/core`.
   - **Missing User Guides:** There is no user-facing guide for `code-graph` (the files in `docs/code-graph/` describe internal SQLite worker threads, IPC, and low-level classes). There is no standalone guide for authoring custom schemas, forking schemas (`specd schema fork`), or extending schemas (`specd schema extend`).
   - **Internal doc gaps:** Non-user docs (`docs/core/`, `docs/code-graph/`, `docs/sdk/`, `docs/cli/`) need full verification against current code to fix gaps, broken references, or outdated contract explanations.

## Approach / Solution Outline

1. **Clean Separation of User vs. Developer Documentation:**
   - `docs/guide/`: Exclusively user-facing and AI-agent facing guides.
   - Non-user documentation: Move internal developer docs (such as `skills-template-rendering.md`) to their appropriate technical package reference locations.
2. **Comprehensive User Guide Catalog (`docs/guide/`):**
   - `getting-started`: Consolidated onboarding, philosophy, directory structure (`specs/`, `.specd/`), core mental model.
   - `configuration`: Unified, authoritative reference for `specd.yaml`, workspaces, storage, cascade resolution, environment variables, and validation rules (reconciling `configuration.md` and `config-reference.md`).
   - `workflow`: Lifecycle states (12 states), transitions, human approval gates (`spec`, `signoff`), hooks, and skill roles.
   - `schemas`: Conceptual guide explaining what schemas are in SpecD, their role in lifecycle governance, artifact DAGs, constraints, and how SpecD uses them.
   - `standard-schema`: Comprehensive guide specifically dedicated to `@specd/schema-std`: the 5 core artifacts (`proposal`, `specs`, `verify`, `design`, `tasks`), the artifact DAG, scope (`change` vs `spec`), rules, constraints, and validation behavior.
   - `custom-schemas`: Practical guide on creating custom schemas, forking existing ones (`specd schema fork`), extending schemas (`specd schema extend`), applying `schemaOverrides` in `specd.yaml`, and authoring/packaging distributable **schema plugins** (`schemaPlugins`) to share workflow rules and custom artifacts across multiple projects.
   - `templates`: Structural template references for `proposal`, `spec`, `verify`, `design`, and `tasks`.
   - `deltas`: Comprehensive guide on `.delta.yaml` authoring: operations (`added`, `modified`, `removed`, `no-op`), selectors, positioning, and merge strategies.
   - `code-graph`: User guide for Code Graph: graph-first protocol, indexing (`graph index`), symbol search (`graph search`), blast-radius impact analysis (`graph impact`), and hotspot detection (`graph hotspots`).
   - `workspaces`: Monorepos, external workspaces, and ownership (`owned`, `shared`, `readOnly`).
   - `selectors`: AST selector syntax for targeting spec sections and structured artifacts.
3. **Total Repository Documentation Audit and Alignment:**
   - Audit **every single file** across `docs/` (`docs/guide/`, `docs/core/`, `docs/code-graph/`, `docs/sdk/`, `docs/cli/`, `docs/config/`, `docs/schemas/`, and `docs/adr/`).
   - Fix all outdated contracts, resolve contradictions, repair links, eliminate obsolete assertions, and verify complete fidelity with codebase implementation.
4. **`specd guide` CLI Command:**
   - Introduce `specd guide [topic]` in `@specd/cli`.
   - Running `specd guide` lists all available topics with one-line descriptions.
   - Running `specd guide <topic>` renders the topic guide.
   - Output format flags: `--format text|markdown|toon` (optimized for developers and LLMs).
   - Bundle the compiled user guides inside `@specd/cli` so external projects have offline, autonomous access.

## Design Decisions & Agreements

- **Standalone `@specd/guide` Package:** Guide catalog, outline extraction, section slicing, and search are isolated in `@specd/guide` (zero runtime dependencies on `@specd/core`). `@specd/cli` and future `@specd/mcp` serve as thin delivery adapters.
- **Zero Runtime Core Dependency:** Markdown parsing (headings, line offsets, frontmatter) happens strictly at build time (`scripts/bundle-guides.ts`). The static catalog is emitted with pre-computed section metadata, achieving $O(1)$ lookups and 0 ms parsing latency at runtime.
- **User Focus for CLI Guide:** The `specd guide` command exposes only user-facing guides. Internal monorepo implementation details (ports, worker threads, SQLite stores) are excluded from the CLI bundle.
- **Three-way Schema Documentation:**
  1. `schemas`: Explaining the concepts, what schemas are, what they do.
  2. `standard-schema`: Dedicated guide explaining the standard `@specd/schema-std` schema in detail.
  3. `custom-schemas`: Guide on how to create, fork, and extend schemas, plus authoring and publishing distributable schema plugins (`schemaPlugins`).
- **Single Source of Truth for Config:** Eliminate the contradiction between `configuration.md` and `config-reference.md`, establishing the layered cascade as canonical.
- **Full Docs Alignment:** The change includes updating and correcting non-user documentation across the repo to leave all documentation pristine.
- **Docusaurus-Standard Frontmatter:** Frontmatter on all `docs/guide/*.md` files strictly uses native Docusaurus fields (`title`, `description`, `sidebar_position`). This guarantees 100% compatibility with `apps/public-web`, enables Docusaurus to populate SEO/meta descriptions automatically, and keeps `apps/public-web/sidebars.ts` in sync with the new guide structure.
- **Search Engine:** In-memory BM25/TF-IDF section search powered by `minisearch` (~7 KB, 0 dependencies). Indexes sections by markdown headings, supports field boosting (`title: 5`, `heading: 3`, `content: 1`), English stop-words filtering, and fuzzy/prefix matching.
- **Agent Instructions Alignment:** Update `agent-instruction.md.tpl` (governed by `skills:agent-instruction-template`) so that the rendered `<specd>` block in `AGENTS.md`, `CLAUDE.md`, and skill templates explicitly instructs agents on how to use `specd guide` for on-demand knowledge retrieval.
- **Command Name:** `specd guide` with subcommands / arguments: `specd guide [topic]` and `specd guide search <query>` with `--format text|markdown|toon`.
