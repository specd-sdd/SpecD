# Exploration Context: complete-guide-config-documentation

Generated: 2026-09-24

## Problem Statement

Following the recent archival of the guide overhaul (`20260923-144548-cli-guide-command` and commit `b5cfe554f`), an exhaustive audit of the codebase against `docs/guide/` revealed that multiple configuration capabilities, variable placeholders, security details, and syntax rules were either omitted, partially documented, or documented with errors.

Specifically, variables for `pattern` in archive paths (`{{month}}`, `{{day}}`) were missing; `specs.fs.metadataPath` was undocumented; template variable substitution in hooks and artifact templates was incomplete or misstated; `docs/guide/context-compilation.md` had a critical bug referencing non-existent `context.include`/`context.exclude` fields; and several default values and adapter syntaxes in `docs/guide/workspaces.md` and `configuration.md` were inconsistent with implementation code.

Per user directive: unsupported variables/patterns and legacy/deprecated formats are completely omitted from documentation. Only current, supported functionality that works today is documented.

## Approach / Solution Outline

1. **Fix `docs/guide/configuration.md`**:
   - Update `storage.archive.fs.pattern` section and table:
     - Document all 6 supported variables: `{{year}}`, `{{month}}`, `{{day}}`, `{{date}}`, `{{change.name}}`, `{{change.archivedName}}`.
     - Correct `{{change.archivedName}}` format description to `YYYYMMDD-HHmmss-<name>` (not `YYYY-MM-DD-<name>`).
     - Clarify that pattern replacement is direct string token substitution (`replaceAll`), not a Nunjucks template.
     - Do not mention unsupported variables.
   - Document `workspaces.<name>.specs.fs.metadataPath` (or under `adapter.config.metadataPath`):
     - Purpose: custom location for workspace spec metadata (`metadata.json`, validation cache).
     - Default resolution: `{specdPath}/metadata` for local workspaces, nearest `.specd/metadata` for external workspaces.
   - Document reserved workspace identifier `'root'` (forbidden in `workspaces`).
   - Document `prefix` validation constraints (`PrefixZodSchema`): regex `/^[a-z0-9_][a-z0-9_-]*$/` per segment, multi-segment separated by `/`, no leading/trailing slashes. Note that prefix is display-only and does not replace `workspace:` in spec IDs.
   - Document `context` optional `id` field: `{ id?: string, file?: string, instruction?: string }` used for cascade removal `remove.context: [{ id: '...' }]`.
   - Document template variables available in `schemaOverrides` hooks (`run:` and `instruction:`): `{{project.root}}`, `{{change.name}}`, `{{change.path}}`, `{{change.archivedName}}` (post-archive). Note shell escaping in `run:` vs verbatim in `instruction:`.
   - Document standard structured `adapter: { type, config }` syntax exclusively (omitting legacy syntax).
