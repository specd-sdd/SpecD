# Exploration Context: retire-spec-layout

Generated: 2026-09-23

## Problem Statement

The spec `default:_global/spec-layout` was created early in the project lifecycle (ADR-0011, February 2026) before the schema engine (`@specd/schema-std`), AST-based artifact validations, and workspace configuration existed.

At the time, it attempted to define two concerns in one place:

1. Monorepo spec directory layout (`specs/_global/` for cross-cutting constraints, `specs/<package>/` for internal specs).
2. Authoring format and required sections of `spec.md` (Purpose, Requirements, Spec Dependencies) and `verify.md` (GIVEN/WHEN/THEN scenarios, Scenario headers).

Since the introduction of `@specd/schema-std`, this spec is entirely obsolete:

- **Markdown structure & validation:** `@specd/schema-std` (`packages/schema-std/schema.yaml` and `specs/schema-std/standard-schema`) now declaratively defines templates, AST section validations, cross-artifact parity rules, and metadata extractors.
- **Filesystem organization:** Directory layout and ownership are configured in `specd.yaml` under `workspaces` and implemented in `@specd/core` via `FsSpecRepository`.
- **Context pollution:** `specd.yaml` specifies `contextIncludeSpecs: ['default:*']`, which injects all global specs into every prompt context across all workflow steps and packages. As a result, agents performing code implementation, testing, or review constantly receive `spec-layout` in context, consuming token budget with redundant authoring instructions.

## Approach / Solution Outline

1. **Update dependent specs:**
   - `cli:spec-search` is the only active spec with a dependency on `default:_global/spec-layout`.
   - Update `specs/cli/spec-search/spec.md` (via delta in this change) to remove `default:_global/spec-layout` from `## Spec Dependencies`.
   - Update `verify.md` (via delta or no-op) as needed.
2. **Retire `default:_global/spec-layout`:**
   - Remove directory `specs/_global/spec-layout/` (including `spec.md`, `verify.md`, and `spec-lock.json`).
   - Remove generated metadata under `.specd/metadata/default/_global/spec-layout/` if present.
3. **Documentation:**
   - Update or add a note to `docs/adr/0011-spec-layout.md` noting that spec formatting and validation were superseded by `@specd/schema-std`.

## Design Decisions

- **Full retirement over context exclusion:** Rather than just adding `default:_global/spec-layout` to `contextExcludeSpecs` in `specd.yaml`, fully retire the spec to eliminate dead specifications and maintenance overhead.
- **Canonical spec schema authority:** `schema-std:standard-schema` remains the authoritative specification for standard spec and verify artifact layout and validation rules.

## Key Codebase Observations

- `specd.yaml` line 35-37 includes `default:*` in all contexts; retiring `_global/spec-layout` directly saves prompt context on all future change steps across the repository.
- `cli:spec-search` declared dependency on `default:_global/spec-layout` because spec search displays and searches specs. Once `spec-layout` is removed, the dependency must be removed from `specDependsOn` and `spec.md`.
