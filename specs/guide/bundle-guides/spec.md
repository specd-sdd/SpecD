# Guide Bundle Compilation

## Purpose

To achieve zero runtime dependency on `@specd/core` and eliminate runtime Markdown parsing latency, `@specd/guide` compiles its guide catalog at package build time. This spec defines the build-time bundling script (`scripts/bundle-guides.ts`), input validation for Docusaurus frontmatter, heading hierarchy parsing, exact line range computation, and generation of the static TypeScript catalog.

## Requirements

### Requirement: Build-Time Compilation Script

The package MUST provide a build-time script (`scripts/bundle-guides.ts`) that runs during `pnpm build` of `@specd/guide`:

- The script MUST compile a configured set of source roots, each mapped to a collection identifier. At minimum the user guide (`docs/guide/`) and the SDK collection MUST be configured, where the SDK collection source roots are `docs/sdk/`, `docs/core/`, `docs/code-graph/`, `docs/skills/` and `docs/schemas/`.
- The script MUST NOT hardcode a single documentation directory.
- The script MUST recurse into subdirectories of each source root. Non-Markdown files and Docusaurus category metadata files (e.g. `_category_.json`) MUST be ignored.
- A nested source document MUST produce a topic equal to its path relative to the collection root, without extension, lowercased, retaining subdirectory separators (e.g. `examples/implementing-a-port`).
- The script MUST parse YAML frontmatter and Markdown headings.
- The script MUST emit the user collection as a static JSON asset at `generated/guides.json` and the SDK collection as a separate static JSON asset at `generated/guides-sdk.json`.
- These package-root JSON assets MUST be the sole generated catalog format. The build MUST NOT emit or consume generated TypeScript catalog modules.
- A normal package build MUST refresh the exact JSON assets used by both source and compiled runtimes and included in the published package; it MUST NOT write a duplicate catalog beneath `src/`.
- The script MUST invoke TypeDoc as a library, over the entry points declared by the public site's curated API entry-point list (`apiPackageEntryPoints`), to generate the public API reference. The script MUST NOT consume a pre-generated or gitignored artifact from another workspace.
- TypeDoc MUST run with options equivalent to the public site's `typedoc.json` (`skipErrorChecking`, `excludePrivate`, `excludeInternal`).
- The script MUST emit one addressable topic per documented symbol, grouped by symbol kind, producing collection-qualified topics of the form `<collection>:<kind-dir>/<symbol>` (e.g. `sdk:classes/ArtifactDag`).
- Because the `@specd/sdk` entry point is the package barrel, the re-exported `@specd/core` surface MUST be reachable transitively through it.

### Requirement: Mandatory Frontmatter Validation

The compilation script MUST validate frontmatter fields for every hand-written file in every configured collection:

- `title`: Non-empty string.
- `description`: Non-empty string.
- `sidebar_position`: Integer greater than or equal to 0.
- If any required frontmatter field is missing, empty, or of invalid type, the script MUST fail the build with an error identifying the offending file and field.
- No lenient or derived fallback is permitted: a missing frontmatter field MUST fail the build rather than be inferred from the document's first heading or first paragraph.

Documentation consumed by the SDK collection has no frontmatter of its own because it is generated by TypeDoc. The script MUST synthesize `title`, `description` and `sidebar_position` for each generated API topic from the TypeDoc reflection, so that generated topics satisfy the same contract and the metadata reported for them is never empty.

### Requirement: Heading and Line Range Extraction

The script MUST parse the Markdown document structure from the body text (excluding YAML frontmatter) to extract sections, line bounds, and character offsets:

- Heading extraction MUST recognize Markdown headings at all levels (`#` through `######`).
- The script MUST compute 1-indexed `startLine` and `endLine` for each section relative to the frontmatter-free document body:
  - `startLine`: The exact line index where the section heading appears.
  - `endLine`: The line immediately preceding the next heading of equal or shallower depth, or the final line of the document for the last section.
- Section line count MUST be computed as `endLine - startLine + 1`.
- The script MUST compute 0-indexed character offsets (`startOffset` and `endOffset`) bounding each section within the clean document body text:
  - `startOffset`: Character index where the section heading begins.
  - `endOffset`: Character index where the section concludes (at the end of `endLine`).

### Requirement: Static Catalog Artifact Generation

Each generated JSON catalog asset MUST:

- Serialize an immutable catalog array of `GuideTopic` records containing all pre-parsed guides for its collection.
- Omit serialized redundant `content` from outline section objects in the catalog, providing `startOffset` and `endOffset` character spans for on-demand runtime extraction.
- Serialize an index map mapping topic identifiers to their corresponding array indices for $O(1)$ lookup.
- Be committed or generated deterministically and included in the published package, so packages depending on `@specd/guide` can load the assets without requiring access to `docs/guide/` or to any SDK collection source root.

The user collection MUST continue to be emitted to `generated/guides.json`. The SDK collection MUST be emitted to `generated/guides-sdk.json`, and the contents of `guides.json` MUST remain unchanged by the addition of the SDK collection. Each collection's catalog MUST remain independently loadable.

The published package MUST contain both JSON assets, and loading either catalog from an extracted package tarball MUST produce the same topic inventory as loading it in the repository build. No generated TypeScript catalog file or legacy `src/infrastructure/generated` asset MAY be required for runtime loading.

## Constraints

- Build script MUST execute purely during package build; runtime code MUST NOT invoke the bundler.
- All line numbers in the generated catalog MUST be 1-indexed.
